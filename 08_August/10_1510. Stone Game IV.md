## 📝 Problem Statement

Alice and Bob take turns playing a game, with **Alice starting first**.

Initially, there are `n` stones in a pile. On each player's turn, that player makes a move consisting of removing **any non-zero square number of stones** (e.g., 1, 4, 9, 16, ...) in the pile.

Also, if a player cannot make a move (i.e., the pile has 0 stones left), he/she loses the game.

Given a positive integer `n`, return `true` if and only if **Alice wins the game**, assuming both players play optimally. Otherwise, return `false`.

---

## 📊 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `n = 1` | `true` | Alice can remove 1 stone (which is a perfect square) to win the game because Bob doesn't have any moves left. |
| **2** | `n = 2` | `false` | Alice can only remove 1 stone. After that, Bob removes the last one winning the game (2 -> 1 -> 0). |
| **3** | `n = 4` | `true` | `n` is already a perfect square. Alice can win with one move by removing 4 stones (4 -> 0). |

---

## 🚫 Constraints

> - `1 <= n <= 10^5`

---

## 🧠 Key Insights

1. **Game Theory & Optimal Play:** Both players play optimally. This means a player will *always* choose a move that forces the opponent into a losing state. If no such move exists, the player is doomed to lose.
2. **Minimax Strategy:** If I am at state `n` (with `n` stones left), I can transition to state `n - k^2`. If there is *at least one* valid `k` such that my opponent loses at state `n - k^2`, then I will definitely pick that `k` and secure my victory.
3. **State Evaluation:**
    * If `n = 0`, the current player has no moves and automatically **loses** (`false`).
    * If `n > 0`, the current player **wins** (`true`) if they can hand over a `false` state to the opponent.

## 💡 Approach

<details>
<summary><b>Click here to expand the approach breakdown</b></summary>

### 1. Recursion + Memoization (Top-Down)
When Alice starts, she iterates through all possible perfect squares `k*k <= n`. For each square removed, the remaining stones `n - k*k` are passed to Bob. 
We can write a recursive function `solve(n)` that returns whether the current player can win. If `solve(n - k*k)` returns `false` (meaning Bob loses), then Alice wins, and we return `true`. To prevent recalculating overlapping subproblems (e.g., reaching state `n=4` from different paths), we memoize the results in a 1D array of size `n+1`.

### 2. Tabulation (Bottom-Up DP)
Instead of dealing with recursion overhead, we can build the answer from `0` to `n`. 
We create a boolean DP array `t` where `t[i]` tells us if the player facing `i` stones will win. 
* Base case: `t[0] = false` (0 stones means you lose).
* We iterate `i` from `1` to `n`. For each `i`, we try every perfect square `k*k <= i`. 
* If we find a `k` where `t[i - (k*k)] == false`, it means taking `k*k` stones leaves the opponent in a guaranteed losing state. Thus, `t[i] = true`.

</details>

## 💻 Solution Code (Recursion + Memoization)

```cpp
// Intuition: The game relies on forcing the opponent into a losing state. If any valid move (removing a perfect square) leaves the remaining stones in a state where the next player loses, the current player can pick that move and win.
// Approach: 
// 1. Use a recursive function `solve(n)` that returns true if the current player wins with `n` stones.
// 2. Base case: If `n == 0`, the current player has no moves and loses (return false).
// 3. Memoize results in array `t` to avoid recomputing states.
// 4. Iterate over all perfect squares `k*k <= n`. If `solve(n - (k*k))` is false, the opponent loses, so the current player wins.
// Time Complexity: O(n * sqrt(n)) - We evaluate n states, and each state loops at most sqrt(n) times.
// Space Complexity: O(n) - For the memoization array and the recursive call stack.

class Solution {
public:
    vector<int> t; 

    bool solve(int n) {
        if(n == 0) {
            return false; // No moves left, current player loses
        }

        if(t[n] != -1) {
            return t[n] == 1 ? true : false; // Return memoized result
        }

        for(int k = 1; k*k <= n; k++) { 
            
            // Call for opponent. If opponent loses (false), we win
            if(solve(n - (k*k)) == false) { 
                return t[n] = true;
            }

        }

        // If no move forces a win, we lose
        return t[n] = false; 

    }

    bool winnerSquareGame(int n) {
        t.assign(n+1, -1);
        return solve(n); // Call to see if Alice (first player) wins
    }
};

/*
*
* Dry Run
* For n = 2:
* 1. solve(2) called. Loop k=1 (k*k = 1 <= 2).
* 2. Call solve(2 - 1) -> solve(1).
* 3. solve(1) called. Loop k=1 (k*k = 1 <= 1).
* 4. Call solve(1 - 1) -> solve(0).
* 5. solve(0) returns false (base case).
* 6. Since solve(0) is false, solve(1) returns true (memoized).
* 7. Back to solve(2): solve(1) is true. No other k is valid (2*2 = 4 > 2).
* 8. Loop ends. solve(2) returns false.
* 9. winnerSquareGame(2) returns false.
*
*/
```

## 🚀 Optimized Solution Code (Bottom-Up DP)

```cpp
// Intuition: Instead of relying on recursion depth, we can iteratively build up the winning states from 0 to n using tabulation.
// Approach: 
// 1. Create a boolean DP array `t` of size n+1 initialized to false.
// 2. Base case: `t[0] = false` because 0 stones means losing.
// 3. For each number of stones `i` from 1 to `n`:
// 4. Try removing all perfect squares `k*k <= i`. 
// 5. If `t[i - (k*k)]` is false, making this move leaves the opponent with a losing state.
// 6. Set `t[i] = true` and break (we found a winning strategy for state `i`).
// 7. Finally, return `t[n]`.
// Time Complexity: O(n * sqrt(n)) - Outer loop runs n times, inner loop runs up to sqrt(i) times.
// Space Complexity: O(n) - Single DP array of size n+1.

class Solution {
public:
    bool winnerSquareGame(int n) {
        vector<bool> t(n+1, false);

        // Base case: 0 stones left means a loss for the current player
        t[0] = false; 

        for(int i = 1; i < n+1; i++) {
            for(int k = 1; k*k <= i; k++) {
                
                // If taking k*k stones gives the opponent a losing state
                if(t[i - (k*k)] == false) {
                    t[i] = true; // Current player wins
                    break;       // No need to check other moves for this i
                }
                
            }
        }

        return t[n]; // Result for initial n stones
    }
};

/*
*
* Dry Run
* For n = 4:
* 1. t[0] = false
* 2. i = 1: k=1. i-k*k = 0. t[0] is false, so t[1] = true.
* 3. i = 2: k=1. i-k*k = 1. t[1] is true. Next k invalid. t[2] remains false.
* 4. i = 3: k=1. i-k*k = 2. t[2] is false, so t[3] = true.
* 5. i = 4: k=1. i-k*k = 3. t[3] is true. Next k=2. 
* 6. i = 4, k=2: i-k*k = 0. t[0] is false, so t[4] = true. Break.
* 7. Loop finishes. t[4] is true. Return true.
*
*/
```

## 📌 Notes
- **Why Bottom-Up?** While the Top-Down (Memoization) approach is intuitive and conceptually aligned with the recursion tree of the game, the Bottom-Up approach is strictly better practically as it avoids stack memory overhead and recursion depth limits.
- **Short-circuiting:** Notice the `break;` statement in the Bottom-Up solution and the direct `return t[n] = true;` in the Top-Down solution. Since we only need *one* winning move, we immediately stop searching once we find a move that guarantees a win.
