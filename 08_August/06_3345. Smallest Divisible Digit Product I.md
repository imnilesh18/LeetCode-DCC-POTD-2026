# 3345. Smallest Divisible Digit Product I

**Problem Link:** [LeetCode - Smallest Divisible Digit Product I](https://leetcode.com/problems/smallest-divisible-digit-product-i/)
**Difficulty:** 🟢 Easy
**Tags:** `Math`, `Enumeration`

---

## 📝 Problem Statement

You are given two integers `n` and `t`. Return the smallest number greater than or equal to `n` such that the product of its digits is divisible by `t`.

---

## ⚙️ Constraints

- `1 <= n <= 100`
- `1 <= t <= 10`

---

## 💡 Examples

### Example 1
| Input | Output | Explanation |
| :--- | :--- | :--- |
| `n = 10`, `t = 2` | `10` | The digit product of 10 is 0, which is divisible by 2, making it the smallest number greater than or equal to 10 that satisfies the condition. |

### Example 2
| Input | Output | Explanation |
| :--- | :--- | :--- |
| `n = 15`, `t = 3` | `16` | The digit product of 16 is 6, which is divisible by 3, making it the smallest number greater than or equal to 15 that satisfies the condition. |

---

## 🧠 Approach

The problem requires us to find the closest number $\ge n$ whose digit product is a multiple of $t$. 
Since the constraints are extremely small ($n \le 100$), we can use a direct **Enumeration** (brute-force) approach. We start checking from $n$ and increment it by $1$ until we find a number that satisfies the condition. 

To calculate the digit product efficiently:
1. Extract the digits one by one using modulo (`% 10`) and division (`/ 10`).
2. Multiply them together.
3. *Optimization:* If the product becomes `0` at any point (i.e., the number contains a `0`), we can stop early because any subsequent multiplication will remain `0`, and `0` is divisible by any integer `t`.

---

## 💻 Solution Code

```cpp
// Intuition: Since we need the smallest number >= n with a digit product divisible by t, we can just check numbers sequentially. The search space is tiny because every multiple of 10 has a digit product of 0, which is divisible by any t.
// Approach: Create a helper function `check` to calculate the digit product. Extract digits, multiply them, and break early if the product hits 0. Increment n until `check(n)` returns true.
// Time Complexity: O(1) or O(log n). We check at most 10 numbers (we will inevitably hit a number ending in 0, giving a product of 0). The digit extraction takes time proportional to the number of digits.
// Space Complexity: O(1). Only a few integer variables are used.
class Solution {
public:
    int smallestNumber(int n, int t) {
        // Lambda function to check if the digit product is divisible by t
        auto check = [&](int num) -> bool {
            int product = 1;
            
            // Extract digits and calculate their product
            while (num) {
                product *= (num % 10); // Multiply by the last digit
                num /= 10;             // Remove the last digit
                
                // Early exit: if product is 0, it will stay 0
                if (!product) {
                    break;
                }
            }
            
            // Return true if the product is a multiple of t
            return !(product % t);
        };
        
        // Increment n until a valid number is found
        while (!check(n)) {
            n++;
        }
        
        return n;
    }
};

/*
*
* Dry Run
* 
* Input: n = 15, t = 3
* 
* Iteration 1: check(15)
* - product = 1
* - num = 15 -> product = 1 * 5 = 5, num = 1
* - num = 1 -> product = 5 * 1 = 5, num = 0
* - returns !(5 % 3) -> !(2) -> false
* - n becomes 16
* 
* Iteration 2: check(16)
* - product = 1
* - num = 16 -> product = 1 * 6 = 6, num = 1
* - num = 1 -> product = 6 * 1 = 6, num = 0
* - returns !(6 % 3) -> !(0) -> true
* 
* Loop ends. Returns 16.
*
*/
```

---

## 🔍 Key Insights

* **Bounded Search Space:** You will never iterate more than 10 times. For example, if you start at `n = 11`, by the time you reach `20`, the digit product becomes `0`, which trivially satisfies `0 % t == 0`.
* **Early Termination:** Breaking the loop as soon as `product == 0` saves unnecessary operations, especially if this logic were to be applied to much larger numbers.
