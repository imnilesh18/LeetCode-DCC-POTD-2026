## 📌 Problem Link
[2948. Make Lexicographically Smallest Array by Swapping Elements](https://leetcode.com/problems/make-lexicographically-smallest-array-by-swapping-elements)

## 📝 Problem Statement

You are given a **0-indexed** array of positive integers `nums` and a positive integer `limit`.

In one operation, you can choose any two indices `i` and `j` and swap `nums[i]` and `nums[j]` if `|nums[i] - nums[j]| <= limit`.

Return the **lexicographically smallest array** that can be obtained by performing the operation any number of times.

> **Note:** An array `a` is lexicographically smaller than an array `b` if in the first position where `a` and `b` differ, array `a` has an element that is less than the corresponding element in `b`. For example, the array `[2,10,3]` is lexicographically smaller than the array `[10,2,3]` because they differ at index `0` and `2 < 10`.

### ⚠️ Constraints:

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `1 <= limit <= 10^9`

## 🧠 Explanation & Approach

### The Core Observation (Transitivity)
At first glance, it feels like we only have local swapping available. However, swapping possesses a **transitive property**. If you can swap element `A` with element `B`, and element `B` with element `C`, then elements `A`, `B`, and `C` form a freely inter-swappable "group". You can arrange all elements within this group in any order you want among their combined original index positions. 

To get the lexicographically smallest array, we naturally want the smallest elements to appear at the earliest indices possible.

### Strategy Breakdown

1. **Brute Force (TLE):** 
   For every index `i`, we can greedily look to the right for the absolute smallest element `nums[j]` where `|nums[i] - nums[j]| <= limit`. We perform this swap and repeatedly check again until no smaller element can be brought forward. This operates in $O(N^3)$ or $O(N^2)$ time, which is too slow for $N = 10^5$.
   
2. **Optimal Grouping via Sorting:**
   - To efficiently find these "groups" of elements that can be swapped amongst each other, we can sort the original array.
   - When sorted, if the absolute difference between two adjacent elements is `<= limit`, they belong to the same group. If the difference is `> limit`, the chain breaks, and a new group begins.
   
3. **Mapping and Queuing:**
   - We maintain a `groupNum` identifier.
   - Using a Hash Map (`unordered_map<int, int>`), we map each value to its assigned `groupNum`.
   - Using another Hash Map (`unordered_map<int, list<int>>`), we map each `groupNum` to a linked list (or queue) of its sorted elements. We use a `list` to allow $O(1)$ removals from the front.

4. **Constructing the Answer:**
   - Iterate through the original, unsorted `nums` array. 
   - For an element `nums[i]`, determine its group. 
   - The optimal element to place at index `i` is the smallest available element from that group. Since our lists are already sorted, this is simply the element at the `front()` of the list. Pop it off and place it in the result array!

```cpp
// Intuition: To get the lexicographically smallest array, we want smaller elements at earlier indices. We can greedily check the right side for any element that is smaller and within the `limit` absolute difference, and swap them.
// Approach: 
// 1. Iterate through each index `i`.
// 2. Continuously search the right side (from `i+1` to `n-1`) for the smallest valid element.
// 3. Swap the current element with the found smallest valid element.
// 4. Repeat this at the same index until no smaller valid element can be swapped.
// Time Complexity: O(N^3) in the worst case due to the while(true) loop and nested linear scans.
// Space Complexity: O(1) as we modify the array in-place.
class Solution {
public:
    vector<int> lexicographicallySmallestArray(vector<int>& nums, int limit) {
        int n = nums.size(); // Get the size of the array

        for(int i = 0; i < n; i++) { // Iterate over each position
            while(true) { // Keep swapping until the smallest valid number is at index i
                int smallValue = nums[i];
                int idx = -1;

                for(int j = i+1; j < n; j++) { // Scan right for a smaller, valid element
                    if(abs(nums[i] - nums[j]) <= limit) { // Check the limit condition
                        if(nums[j] < smallValue) { // Ensure it makes our array lexicographically smaller
                            smallValue = nums[j];
                            idx = j; // Track the index of the best candidate
                        }
                    }
                }

                if(idx != -1) { // If a valid candidate was found
                    swap(nums[i], nums[idx]); // Perform the swap
                } else {
                    break; // Break when no smaller element can be brought to index i
                }
            }
        }

        return nums; // Return the final modified array
    }
};

/*
*
* Dry Run
* Input: nums = [1,5,3,9,8], limit = 2
* i = 0: nums[0]=1. Smallest valid on right is none. Break.
* i = 1: nums[1]=5. Smallest valid on right <= 5+2 is 3 (at idx 2). Swap 5 and 3. Array: [1,3,5,9,8].
* i = 1 (again): nums[1]=3. No smaller valid. Break.
* i = 2: nums[2]=5. No smaller valid. Break.
* i = 3: nums[3]=9. Smallest valid on right <= 9+2 is 8 (at idx 4). Swap 9 and 8. Array: [1,3,5,8,9].
* i = 3 (again): nums[3]=8. No smaller valid. Break.
* i = 4: nums[4]=9. Loop ends.
* Final Output: [1,3,5,8,9]
*
*/
```

```cpp
// Intuition: If element A can swap with B, and B with C, then A, B, and C form a group and can be placed in any order among their original indices. By sorting the array, adjacent elements with a difference <= limit belong to the same group.
// Approach: 
// 1. Create a sorted copy of the input array.
// 2. Iterate through the sorted array and group elements. If the difference between adjacent elements exceeds the `limit`, start a new group.
// 3. Map each number to its group ID and maintain a sorted list of elements for each group.
// 4. Iterate through the original array. For each element, look up its group ID, extract the smallest available number from that group's list (which is at the front), and place it in the result.
// Time Complexity: O(N log N) dominated by the sorting step. Grouping and building the result takes O(N) time.
// Space Complexity: O(N) auxiliary space used for the sorted array, hash maps, and lists.
class Solution {
public:
    vector<int> lexicographicallySmallestArray(vector<int>& nums, int limit) {
        int n = nums.size(); // Get the size of the array

        vector<int> vec = nums; // Create a copy of the array
        // Sort the array to easily identify swappable groups
        sort(begin(vec), end(vec));

        int groupNum = 0; // Initialize the first group ID
        unordered_map<int, int> numToGroup; // Map to store which number belongs to which group ID
        numToGroup[vec[0]] = groupNum; // Assign the first sorted element to group 0

        unordered_map<int, list<int>> groupToList; // Map group IDs to a linked list of their sorted elements
        groupToList[groupNum].push_back(vec[0]); // Add the first element (O(1) insertion)

        for(int i = 1; i < n; i++) { // Group the remaining elements
            if(abs(vec[i] - vec[i-1]) > limit) { // If difference exceeds limit, the chain breaks
                groupNum += 1; // Start a new group
            }

            numToGroup[vec[i]] = groupNum; // Map current number to its calculated group
            groupToList[groupNum].push_back(vec[i]); // Append it to the back of the group's list
        }
        
        // Build the final lexicographically smallest array
        vector<int> result(n);
        for(int i = 0; i < n; i++) { // Iterate based on the original array's order
            int num = nums[i]; // Get the original element
            int group = numToGroup[num]; // Find out which group it belongs to
            
            // The smallest available number in this group is always at the front of its list
            result[i] = *groupToList[group].begin(); 
            groupToList[group].pop_front(); // Remove the used element from the list in O(1) time
        }

        return result; // Return the reconstructed optimal array
    }
};

/*
*
* Dry Run
* Input: nums = [1,5,3,9,8], limit = 2
* Sorted vec = [1,3,5,8,9]
* Grouping:
* vec[1]-vec[0] = 3-1 = 2 <= 2 -> 1,3 in Group 0
* vec[2]-vec[1] = 5-3 = 2 <= 2 -> 1,3,5 in Group 0
* vec[3]-vec[2] = 8-5 = 3 > 2  -> start Group 1. 8 in Group 1
* vec[4]-vec[3] = 9-8 = 1 <= 2 -> 8,9 in Group 1
* Maps Generated:
* numToGroup: {1:0, 3:0, 5:0, 8:1, 9:1}
* groupToList: {0: [1,3,5], 1: [8,9]}
* Building Result (Iterating over original nums [1,5,3,9,8]):
* i=0, num=1 -> grp 0 -> pop front (1). result=[1]
* i=1, num=5 -> grp 0 -> pop front (3). result=[1,3]
* i=2, num=3 -> grp 0 -> pop front (5). result=[1,3,5]
* i=3, num=9 -> grp 1 -> pop front (8). result=[1,3,5,8]
* i=4, num=8 -> grp 1 -> pop front (9). result=[1,3,5,8,9]
* Output: [1,3,5,8,9]
*
*/
```

## 🔍 Key Insights & Notes

- **Using `std::list`**: In C++, `std::list` is implemented as a doubly-linked list. It provides $O(1)$ time complexity for `pop_front()`. If we used `std::vector`, `pop_front()` (or `erase(begin())`) would take $O(N)$ time as it shifts all remaining elements, potentially causing a Time Limit Exceeded (TLE) verdict.
- **Transitivity Application**: The core trick of the problem revolves around the fact that overlapping swap pairs bridge disconnected endpoints together into entire sortable components.
