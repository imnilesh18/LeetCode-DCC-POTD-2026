# 3517. Smallest Palindromic Rearrangement I

**Problem Link:** [LeetCode - Smallest Palindromic Rearrangement I](https://leetcode.com/problems/smallest-palindromic-rearrangement-i/)
**Difficulty:** Medium
**Tags:** `String`, `Sorting`, `Counting Sort`

---

## 📝 Problem Statement

You are given a palindromic string `s`.  
Return the **lexicographically smallest** palindromic permutation of `s`.

---

## 🚀 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `s = "z"` | `"z"` | A string of only one character is already the lexicographically smallest palindrome. |
| **2** | `s = "babab"` | `"abbba"` | Rearranging `"babab"` → `"abbba"` gives the smallest lexicographic palindrome. |
| **3** | `s = "daccad"` | `"acddca"` | Rearranging `"daccad"` → `"acddca"` gives the smallest lexicographic palindrome. |

---

## ⚠️ Constraints

- `1 <= s.length <= 10^5`
- `s` consists of lowercase English letters.
- `s` is guaranteed to be palindromic.

---

## 💡 Approach & Key Insights

Since the given string is **already a palindrome**, it possesses a perfect mirror property around its center. To find the lexicographically smallest valid palindrome, we don't need to overcomplicate things with complex permutations. 

Instead, we can greedily optimize the **left half** of the string. 
1. **Split & Sort:** We take the first half of the string and sort it in ascending order. This guarantees the lexicographically smallest prefix.
2. **Mirror:** Because a palindrome must reflect its left side on its right side, we simply take this newly sorted left half and mirror it directly onto the right half.
3. **Odd-Length Safety:** If the string length is odd, the exact middle character acts as the mirror's axis. By sorting only the characters *strictly before* the midpoint and only mirroring those, the middle character naturally remains untouched and perfectly in place!

### Brute-force Solution (C++)

```cpp
// Intuition: Generate all unique permutations in lexicographical order, checking each to see if it forms a palindrome. The first one found is the answer.
// Approach: 1. Sort the string to start with the lexicographically smallest permutation. 2. Use next_permutation to iterate. 3. Check palindrome property on each iteration.
// Time Complexity: O(N! * N) in the worst case, as generating permutations is factorial time, and palindrome check is linear. Will give TLE.
// Space Complexity: O(1) auxiliary space, modified in-place.

class Solution {
public:
    bool isPalindrome(const string& s) {
        int left = 0, right = s.length() - 1;
        while (left < right) {
            if (s[left++] != s[right--]) return false;
        }
        return true;
    }

    string smallestPalindrome(string s) {
        // Sort string to ensure permutations start from lexicographically smallest
        sort(s.begin(), s.end());
        
        // Generate permutations
        do {
            if (isPalindrome(s)) {
                return s;
            }
        } while (next_permutation(s.begin(), s.end()));
        
        return s;
    }
};

/*
*
* Dry Run
* Input: s = "babab"
* Sort: "aabbb"
* Permutations generated sequentially:
* "aabbb" -> not palindrome
* "ababb" -> not palindrome
* "abbab" -> not palindrome
* "abbba" -> valid palindrome! Return "abbba"
*
*/
```

### Optimized Solution (C++)

```cpp
// Intuition: A palindrome mirrors its left half onto its right half. To get the lexicographically smallest palindrome, we just need to sort the left half and mirror it to the right.
// Approach: 1. Calculate length and find the midpoint. 2. Sort the characters in the first half of the string. 3. Mirror these sorted characters onto the second half using a loop.
// Time Complexity: O(N log N) where N is the length of the string, due to sorting the first half. The mirroring takes O(N) time.
// Space Complexity: O(1) auxiliary space (ignoring the space taken for sorting internally), as we modify the string in-place.

class Solution {
public:
    string smallestPalindrome(string s) {
        // Get the total length of the string
        int n   = s.length();
        // Calculate the midpoint boundary
        int mid = n/2;

        // Sort the first half to achieve lexicographically smallest prefix
        sort(s.begin(), s.begin() + mid); //note : mid is not included i.e. [begin, mid)

        // Mirror the sorted left half onto the right half
        for (int i = 0; i < mid; i++) {
            s[n - 1 - i] = s[i];
        }

        // Return the successfully rearranged string
        return s;
    }
};

/*
*
* Dry Run
* Input: s = "daccad"
* Initial variables: n = 6, mid = 3
* First half extraction: Indices 0 to 2 ("dac")
* Sorting first half: "dac" becomes "acd"
* State of s after sort: "acdcad"
* 
* Mirroring loop:
* i = 0: s[5] = s[0] ('a') -> string becomes "acdcda"
* i = 1: s[4] = s[1] ('c') -> string becomes "acdcca"
* i = 2: s[3] = s[2] ('d') -> string becomes "acddca"
* 
* Final Output: "acddca"
*
*/
```

## 🧠 Notes & Further Exploration
* **Why not $O(N)$?** While Counting Sort could technically bring the time complexity down to $O(N)$ because there are only 26 lowercase English letters, utilizing the built-in `std::sort` for $O(N \log N)$ is extremely fast, highly optimized, and requires fewer lines of code. For constraints up to $10^5$, $O(N \log N)$ easily passes within milliseconds.
* **Middle Character Logic:** Notice how the `mid` calculation safely handles odd-length strings via integer division truncation (e.g., $5 / 2 = 2$). Index `2` (the 3rd character) acts as the fixed center point and is excluded from both the sorting range and the mirror loop.
