## 📋 Problem Statement

You are given an integer array `nums` and two integers `l` and `r`[cite: 1]. Your task is to find the **minimum sum** of a subarray whose size is between `l` and `r` (inclusive) and whose sum is **greater than `0`**[cite: 1].

Return the minimum sum of such a subarray[cite: 1]. If no such subarray exists, return `-1`[cite: 1].

> **Note:** A **subarray** is a contiguous non-empty sequence of elements within an array[cite: 1].

---

## 🔒 Constraints

- $1 \le \text{nums.length} \le 100$[cite: 1]
- $1 \le l \le r \le \text{nums.length}$[cite: 1]
- $-1000 \le \text{nums}[i] \le 1000$[cite: 1]

## 🧠 Approach

Because `nums.length` is at most `100`, even straightforward nested-loop approaches pass all test cases[cite: 1]. However, we can progressively optimize from a pure brute-force scan to a prefix-sum length scan, and finally to an $O(n \log n)$ sliding-window + binary-search solution[cite: 1].

### 1. Approach 1: Super Brute Force (Two Pointers)
- Fix the starting index `i` from `0` to `n - 1`[cite: 1].
- Expand the ending index `j` starting from `i`, maintaining a running `currSum` on the fly[cite: 1].
- The current subarray length is `j - i + 1`[cite: 1]. Keep advancing `j` only while `j < n` and `(j - i + 1) <= r`[cite: 1]. Once the length exceeds `r`, break out of the inner loop immediately[cite: 1].
- Whenever `(j - i + 1) >= l` and `currSum > 0`, update `result = min(result, currSum)`[cite: 1].
- **Complexity:** Time $O(n \cdot r)$ | Space $O(1)$[cite: 1].

### 2. Approach 2: Improved Brute Force (Prefix Sum + Valid Lengths Only)
- **Bottleneck in Approach 1:** Starting `j` at `i` wastes iterations checking subarrays of lengths `1, 2, ..., l - 1` when `l > 1`[cite: 1].
- **Optimization:** Precompute a `prefixSum` array so any subarray sum from `i` to `j` can be retrieved in $O(1)$ time using `prefixSum[j] - (i > 0 ? prefixSum[i - 1] : 0)`[cite: 1].
- For each starting index `i`, iterate `len` directly from `l` to `r` (while `i + len <= n`) and compute `j = i + len - 1`[cite: 1].
- Check if `sum > 0` and minimize `result`[cite: 1].
- **Complexity:** Time $O(n \cdot (r - l + 1))$ | Space $O(n)$[cite: 1].

### 3. Approach 3: Optimal Approach (Prefix Sum + Sliding Window + Multiset)
To answer the interview follow-up—*"Can we optimize further?"*—we eliminate the inner loop over lengths using algebra and binary search[cite: 1]:

1. **Mathematical Derivation of Valid Left Endpoints:**
   - For a fixed right endpoint `j` and a left endpoint `i`, the subarray sum is[cite: 1]:
     $$\text{sum}(i, j) = \text{prefixSum}[j] - \text{prefixSum}[i - 1]$$
   - Let $\text{idx} = i - 1$[cite: 1]. The length constraint $l \le j - i + 1 \le r$ rewrites as[cite: 1]:
     $$l \le j - \text{idx} \le r$$
   - Multiplying by $-1$ (which flips the inequalities) and adding $j$ across all terms isolates $\text{idx}$[cite: 1]:
     $$-l \ge \text{idx} - j \ge -r \implies j - r \le \text{idx} \le j - l$$
   - Thus, for any right index `j`, valid values of $\text{idx} = i - 1$ form a **sliding window** $[j - r, j - l]$[cite: 1].

2. **Minimizing a Strictly Positive Sum via `lower_bound`:**
   - We require $\text{prefixSum}[j] - \text{prefixSum}[\text{idx}] > 0$, meaning $\text{prefixSum}[\text{idx}]$ must be **strictly smaller** than $\text{prefixSum}[j]$ (if equal, the sum is $0$, which is invalid)[cite: 1].
   - To **minimize** $\text{prefixSum}[j] - \text{prefixSum}[\text{idx}]$, we want $\text{prefixSum}[\text{idx}]$ to be **as large as possible** while still strictly less than $\text{prefixSum}[j]$[cite: 1].
   - In a sorted container of active window prefix sums, `st.lower_bound(prefixSum[j])` finds the first element $\ge \text{prefixSum}[j]$[cite: 1]. If `it != st.begin()`, decrementing `it--` gives the exact largest element strictly smaller than `prefixSum[j]`[cite: 1]!

3. **Why `std::multiset` Instead of `std::set`?**
   - Because `nums` contains negative values and zeros, different indices can share the exact same prefix sum[cite: 1]. A `std::set` would collapse duplicates, causing premature removal when one index slides out of the window[cite: 1]. A `std::multiset` keeps elements sorted while preserving duplicate counts[cite: 1].

4. **Handling Window Boundaries & the `-1` Prefix Edge Case:**
   - Start `j` at `l - 1` (any smaller `j` cannot form a subarray of length $\ge l$)[cite: 1].
   - **Pre-insert `0`:** When `j = l - 1`, the subarray `[0 ... l - 1]` has length `l`, corresponding to `i = 0` and `idx = i - 1 = -1`[cite: 1]. Since an empty prefix before index `0` has sum `0`, we insert `0` into `st` beforehand so subarrays starting at index `0` are captured[cite: 1].
   - **Entering the window:** When `j - l >= 0`, insert `prefixSum[j - l]`[cite: 1].
   - **Leaving the window:** As `j` moves right, `outOld = j - r - 1` exits the valid range $[j - r, j - l]$[cite: 1]:
     - If `outOld >= 0`, erase one copy of `prefixSum[outOld]` via `st.erase(st.find(prefixSum[outOld]))`[cite: 1].
     - If `outOld == -1`, the virtual `-1` prefix (`0`) has slid out of range (subarrays starting at `0` now have length $r + 1 > r$), so erase one copy of `0` via `st.erase(st.find(0))`[cite: 1].
- **Complexity:** Time $O(n \log n)$ | Space $O(n)$[cite: 1].

## 💻 Solution Code

### 1. Brute Force Approach (Two Pointers)

```cpp
// Intuition: Check all contiguous subarrays with length between l and r, tracking the smallest sum strictly greater than 0.
// Approach: Fix each starting index i, expand ending index j while length (j - i + 1) <= r, accumulate currSum, and update result whenever length >= l and currSum > 0.
// Time Complexity: O(n * r) - Outer loop runs n times and inner loop runs at most r times per start index.
// Space Complexity: O(1) - Only constant extra variables are used.

//Approach-1 (Super Brute Force)
//T.C : O(n*r)
//S.C : O(1)
class Solution {
public:
    int minimumSumSubarray(vector<int>& nums, int l, int r) {
        int n = nums.size();
        int result = INT_MAX;
    
        for (int i = 0; i < n; ++i) {
            int currSum = 0;

            // Expand j while subarray length stays within r
            for (int j = i; j < n && (j - i + 1) <= r; ++j) {
                currSum += nums[j];

                // Check valid minimum length l and strictly positive sum
                if ((j - i + 1) >= l && currSum > 0) {
                    result = min(result, currSum);
                }
            }
        }

        return result == INT_MAX ? -1 : result;    
    }
};

/*
 *
 * Dry Run
 *
 * Input: nums = [3, -2, 1, 4], l = 2, r = 3
 * Initial: n = 4, result = INT_MAX
 *
 * i = 0:
 *   j = 0 -> len = 1, currSum = 3 (len < 2, skip)
 *   j = 1 -> len = 2, currSum = 1 (len >= 2 && currSum > 0 -> result = 1)
 *   j = 2 -> len = 3, currSum = 2 (len >= 2 && currSum > 0 -> result = min(1, 2) = 1)
 *   j = 3 -> len = 4 > r (loop terminates)
 *
 * i = 1:
 *   j = 1 -> len = 1, currSum = -2 (len < 2, skip)
 *   j = 2 -> len = 2, currSum = -1 (currSum <= 0, skip)
 *   j = 3 -> len = 3, currSum = 3 (len >= 2 && currSum > 0 -> result = min(1, 3) = 1)
 *
 * i = 2:
 *   j = 2 -> len = 1, currSum = 1 (len < 2, skip)
 *   j = 3 -> len = 2, currSum = 5 (len >= 2 && currSum > 0 -> result = min(1, 5) = 1)
 *
 * i = 3:
 *   j = 3 -> len = 1, currSum = 4 (len < 2, skip)
 *
 * Final Output: 1
 *
 */
```

### 2. Improved Brute Force Approach (Prefix Sum + Valid Lengths)

```cpp
// Intuition: Skip invalid subarray lengths smaller than l by jumping directly to valid lengths [l, r] and querying subarray sums in O(1) via prefix sums.
// Approach: Build a prefixSum array, iterate over each start index i, iterate valid lengths len from l to r, compute subarray sum in O(1), and track the minimum positive sum.
// Time Complexity: O(n * (r - l + 1)) - For each of the n indices, we only check (r - l + 1) valid lengths.
// Space Complexity: O(n) - Auxiliary prefixSum vector of size n.

//Approach-2 (Improved Brute Force)
//T.C : O(n*(r-l+1))
//S.C : O(n)
class Solution {
public:
    int minimumSumSubarray(vector<int>& nums, int l, int r) {
        int n = nums.size();

        vector<int> prefixSum(n, 0);

        // Precompute prefix sums for O(1) range sum queries
        prefixSum[0] = nums[0];
        for (int i = 1; i < n; i++) {
            prefixSum[i] = prefixSum[i - 1] + nums[i];
        }

        int result = INT_MAX;
        for (int i = 0; i < n; i++) {

            // Iterate directly over valid subarray lengths from l to r
            for (int len = l; len <= r && i + len <= n; len++) {
                int j = i + len - 1;

                // Calculate subarray sum [i..j] in O(1)
                int sum = prefixSum[j] - (i > 0 ? prefixSum[i - 1] : 0);

                if (sum > 0) 
                    result = min(result, sum);
            }
        }

        return result == INT_MAX ? -1 : result;
    }
};

/*
 *
 * Dry Run
 *
 * Input: nums = [3, -2, 1, 4], l = 2, r = 3
 * prefixSum = [3, 1, 2, 6], result = INT_MAX
 *
 * i = 0:
 *   len = 2 -> j = 1, sum = prefixSum[1] - 0 = 1 > 0 -> result = 1
 *   len = 3 -> j = 2, sum = prefixSum[2] - 0 = 2 > 0 -> result = min(1, 2) = 1
 *
 * i = 1:
 *   len = 2 -> j = 2, sum = prefixSum[2] - prefixSum[0] = 2 - 3 = -1 (<= 0, skip)
 *   len = 3 -> j = 3, sum = prefixSum[3] - prefixSum[0] = 6 - 3 = 3 > 0 -> result = min(1, 3) = 1
 *
 * i = 2:
 *   len = 2 -> j = 3, sum = prefixSum[3] - prefixSum[1] = 6 - 1 = 5 > 0 -> result = min(1, 5) = 1
 *   len = 3 -> i + len = 5 > 4 (loop terminates)
 *
 * i = 3:
 *   len = 2 -> i + len = 5 > 4 (loop terminates)
 *
 * Final Output: 1
 *
 */
```

### 3. Optimized Approach (Prefix Sum + Sliding Window + Multiset)

```cpp
// Intuition: For each right endpoint j, valid left prefix indices idx = i - 1 lie in [j - r, j - l]; we want the largest prefixSum[idx] strictly less than prefixSum[j] to minimize the positive difference.
// Approach: Maintain active window prefix sums in a multiset (seeded with 0 for index -1), slide j from l - 1 to n - 1, insert entering prefix sums, erase expiring ones, and binary search using lower_bound.
// Time Complexity: O(n log n) - Each element is inserted, queried via lower_bound, and erased from the multiset at most once in O(log n).
// Space Complexity: O(n) - Prefix sum array and multiset store at most O(n) elements.

//Approach-3 (Using Sliding Window and Multiset)
//T.C : O(nlogn)
//S.C : O(n)
class Solution {
public:
    int minimumSumSubarray(vector<int>& nums, int l, int r) {
        int n = nums.size();

        vector<int> prefixSum(n, 0);
        prefixSum[0] = nums[0];
        for (int i = 1; i < n; i++) {
            prefixSum[i] = prefixSum[i - 1] + nums[i];
        }

        // Multiset stores valid prefix sums in sorted order while allowing duplicates
        multiset<int> st;
        st.insert(0); // Represents prefix sum at virtual index -1 (subarrays starting at index 0)

        int result = INT_MAX;

        for(int j = l-1; j < n; j++) {
            // Insert newly valid left prefix index (j - l) into the window
            if(j - l >= 0) {
                st.insert(prefixSum[j-l]);
            }

            // Remove prefix index (j - r - 1) that has fallen out of window [j - r, j - l]
            int outOld = j-r-1;
            if(outOld >= 0) {
                st.erase(st.find(prefixSum[outOld]));
            } else if(outOld == -1) {
                st.erase(st.find(0));
            }

            // Find largest prefix sum in window strictly smaller than prefixSum[j]
            auto it = st.lower_bound(prefixSum[j]);
            if(it != begin(st)) {
                it--;
                result = min(result, prefixSum[j] - *it);
            }
        }
        return result == INT_MAX ? -1 : result;
    }
};

/*
 *
 * Dry Run
 *
 * Input: nums = [3, -2, 1, 4], l = 2, r = 3
 * prefixSum = [3, 1, 2, 6]
 * Initial: st = {0}, result = INT_MAX
 *
 * j = 1 (prefixSum[1] = 1):
 *   j - l = -1 (no insert)
 *   outOld = 1 - 3 - 1 = -3 (no erase)
 *   st = {0}
 *   lower_bound(1) -> end(st), decrement it -> *it = 0
 *   result = min(INT_MAX, 1 - 0) = 1
 *
 * j = 2 (prefixSum[2] = 2):
 *   j - l = 0 -> insert prefixSum[0] = 3 -> st = {0, 3}
 *   outOld = 2 - 3 - 1 = -2 (no erase)
 *   lower_bound(2) -> points to 3, decrement it -> *it = 0
 *   result = min(1, 2 - 0) = 1
 *
 * j = 3 (prefixSum[3] = 6):
 *   j - l = 1 -> insert prefixSum[1] = 1 -> st = {0, 1, 3}
 *   outOld = 3 - 3 - 1 = -1 -> erase 0 -> st = {1, 3}
 *   lower_bound(6) -> end(st), decrement it -> *it = 3
 *   result = min(1, 6 - 3) = 1
 *
 * Final Output: 1
 *
 */
```

## 📝 Notes

- **Sentinel `0` in `multiset`:** Pre-inserting `0` represents `prefixSum[-1] = 0`, which is essential for evaluating subarrays that begin at index `0` (i.e., `i = 0`, so `idx = i - 1 = -1`)[cite: 1].
- **Expiring the Sentinel `0`:** Once `j` reaches `r + 1`, `outOld = j - r - 1` equals `-1`[cite: 1]. At this point, any subarray starting at index `0` has length `> r` and is invalid, so `0` must be removed via `st.erase(st.find(0))`[cite: 1].
- **Single-Element Erasure:** Always pass an iterator (`st.erase(st.find(val))`) rather than a value (`st.erase(val)`), because `st.erase(val)` removes *all* duplicate occurrences of `val` in a `std::multiset`.
- **Fallback Value:** If `result` remains `INT_MAX` after scanning the entire array, no subarray of length `[l, r]` had a strictly positive sum, so return `-1`[cite: 1].

---

## 🔑 Key Insights

- **Transforming Subarray Bounds into a Sliding Window:** Rewriting $l \le j - i + 1 \le r$ as $j - r \le i - 1 \le j - l$ converts a variable-size subarray search into a fixed-width sliding window over historical prefix sums[cite: 1].
- **Dual Optimization Condition:** Because we need $\text{prefixSum}[j] - \text{prefixSum}[\text{idx}] > 0$ to be as **small** as possible, we need $\text{prefixSum}[\text{idx}]$ to be strictly **less** than $\text{prefixSum}[j]$ yet as **close** to $\text{prefixSum}[j]$ as possible—the exact behavior of `lower_bound(prefixSum[j])` followed by `--it`[cite: 1].
- **Why `std::multiset` is Mandatory:** Negative numbers and zeros in `nums` frequently produce duplicate prefix sums across different indices[cite: 1]. Using `std::set` loses multiplicity information and causes bugs when sliding the window forward[cite: 1].
