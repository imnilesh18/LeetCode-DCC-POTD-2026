## 📝 Problem Statement

You have `k` servers numbered from `0` to `k-1` that are being used to handle multiple requests simultaneously. Each server has infinite computational capacity but cannot handle more than one request at a time. The requests are assigned to servers according to a specific algorithm:

1. The `ith` (0-indexed) request arrives.
2. If all servers are busy, the request is dropped (not handled at all).
3. If the `(i % k)th` server is available, assign the request to that server.
4. Otherwise, assign the request to the next available server (wrapping around the list of servers and starting from `0` if necessary). For example, if the `ith` server is busy, try to assign the request to the `(i+1)th` server, then the `(i+2)th` server, and so on.

You are given a strictly increasing array `arrival` of positive integers, where `arrival[i]` represents the arrival time of the `ith` request, and another array `load`, where `load[i]` represents the load of the `ith` request (the time it takes to complete). 

Your goal is to find the **busiest server(s)**. A server is considered busiest if it handled the most number of requests successfully among all the servers. Return a list containing the IDs (0-indexed) of the busiest server(s) in any order.

---

## ⚙️ Constraints

* `1 <= k <= 10^5`
* `1 <= arrival.length, load.length <= 10^5`
* `arrival.length == load.length`
* `1 <= arrival[i], load[i] <= 10^9`
* `arrival` is strictly increasing.

## 🧠 Approach & Explanation

To efficiently track available and busy servers without hitting a Time Limit Exceeded (TLE) error, we need optimal data structures. A brute-force approach (iterating through all `k` servers for every request) would result in an $O(N \times K)$ time complexity, which is too slow for constraints up to $10^5$. 

Instead, we can optimize this to $O(N \log K)$ by maintaining two specialized data structures:

1. **Available Servers (Ordered Set):** We use a balanced binary search tree (like `std::set` in C++) to store the IDs of currently free servers. This allows us to find the next available server in $O(\log K)$ time using the `lower_bound` function. If `lower_bound` reaches the end (meaning no available servers have an ID $\ge i \% k$), we can easily "wrap around" by picking the first element in the set (`set.begin()`).
2. **Busy Servers (Min-Heap):** We use a Priority Queue (Min-Heap) to keep track of currently occupied servers. The heap stores pairs of `{finish_time, server_id}` and is ordered by the `finish_time`. This way, the server that will be freed the earliest is always at the top of the heap.

**Algorithm Walkthrough:**
* Initialize a set with all server IDs from `0` to `k-1`.
* Initialize an empty min-heap for busy servers.
* Initialize a frequency array `countRequests` of size `k` to track assignments.
* For each incoming request at `arrival[i]` with a specific `load[i]`:
  * **Free Up Servers:** Check the top of the min-heap. If the top server's `finish_time` is $\le$ the current request's `arrival[i]`, pop it from the heap and insert its ID back into the available set. Repeat this until the heap is empty or the top server is still busy.
  * **Find Target:** Calculate the preferred server ID: `target = i % k`.
  * **Assign Request:** Use `lower_bound(target)` on the available set. If it returns the end of the set, wrap around to `begin()`. If the set is completely empty, drop the request.
  * **Update Status:** Remove the selected server from the available set, push it into the min-heap with its new finish time (`arrival[i] + load[i]`), and increment its handled request count.
* Finally, find the maximum value in the frequency array and collect all server IDs that match this maximum value.

### Optimized Solution (C++)
```cpp
// Intuition: We need to efficiently track which servers are available and which are busy. An ordered set helps find the next available server using lower_bound, while a min-heap helps track when busy servers will become free based on their finish times.
// Approach: 
// 1. Maintain a set of `available_servers` (initially 0 to k-1).
// 2. Maintain a min-heap `busyServers` storing {finish_time, server_id}.
// 3. Iterate through each request:
//    a. Free servers whose finish_time <= current request's arrival time.
//    b. Find the preferred server (i % k).
//    c. Use lower_bound to find the next available server (wrapping around if needed).
//    d. If available, assign the request, move the server to `busyServers`, and increment its count.
// 4. Return all servers with the maximum request count.
// Time Complexity: O(N log K) where N is arrival.size() and K is the number of servers.
// Space Complexity: O(K) to store the servers in the set, heap, and frequency array.
class Solution {
public:
    typedef pair<int, int> P; //{finishTime, serverId}

    vector<int> busiestServers(int k, vector<int>& arrival, vector<int>& load) {
        set<int> available_servers;
        // Populate all servers initially as available
        for(int i = 0; i < k; i++) {
            available_servers.insert(i); 
        }

        // Min-heap to track busy servers, ordered by earliest finish time
        priority_queue<P, vector<P>, greater<P>> busyServers;
        vector<int> countRequests(k, 0);

        // Process each request one by one
        for(int i = 0; i < arrival.size(); i++) {
            int time = arrival[i];

            // Free up servers that have completed their tasks by the current time
            while(!busyServers.empty() && busyServers.top().first <= time) {
                int server = busyServers.top().second;
                busyServers.pop();
                available_servers.insert(server);
            }

            int target = i % k; // Preferred server index
            auto it = available_servers.lower_bound(target);

            // Wrap around to the beginning if no servers >= target are available
            if(it == available_servers.end()) { 
                it = available_servers.begin();
            }

            // If the set is completely empty, drop the request
            if(available_servers.empty()) {
                continue; 
            }

            int targetServer = *it;
            available_servers.erase(it); // Mark server as busy

            // Push to heap with its new finish time (arrival + load)
            busyServers.push({time + load[i], targetServer});
            countRequests[targetServer]++;
        }

        // Find the maximum number of requests handled by any single server
        int maxNumberOfRequests = *max_element(begin(countRequests), end(countRequests)); 
        vector<int> result;

        // Collect all servers that tie for the maximum requests
        for(int i = 0; i < k; i++) {
            if(countRequests[i] == maxNumberOfRequests) {
                result.push_back(i);
            }
        }

        return result;
    }
};

/*
*
* Dry Run
*
* Input: k = 3, arrival = [1,2,3,4,5], load = [5,2,3,3,3]
* Init: available = {0, 1, 2}, busy = [], counts = [0, 0, 0]
* 
* i=0 (time=1): preferred=0. Assign to server 0. Finish time: 1+5=6.
*   available = {1, 2}, busy = [{6, 0}], counts = [1, 0, 0]
* i=1 (time=2): preferred=1. Assign to server 1. Finish time: 2+2=4.
*   available = {2}, busy = [{4, 1}, {6, 0}], counts = [1, 1, 0]
* i=2 (time=3): preferred=2. Assign to server 2. Finish time: 3+3=6.
*   available = {}, busy = [{4, 1}, {6, 0}, {6, 2}], counts = [1, 1, 1]
* i=3 (time=4): free server 1 (4 <= 4). preferred=0. Lower_bound(0) wraps to 1. Assign to server 1.
*   available = {}, busy = [{6, 0}, {6, 2}, {7, 1}], counts = [1, 2, 1]
* i=4 (time=5): no servers free (all finish >= 6). Drop request.
*   available = {}.
*
* Max requests = 2 (Handled by server 1).
* Output: [1]
*/
```

## 📌 Notes

* **Data Structure Synergy:** The combination of `std::set` (for spatial ordering/searching of IDs) and `std::priority_queue` (for temporal ordering of finish times) is a powerful pattern for resource-allocation simulation problems.
* **Wrap-Around Logic:** The `lower_bound` method natively solves the "next available" constraint efficiently, and checking against `set.end()` handles the modular wrap-around elegantly.

---

## 🔍 Key Insights

* Half the battle in Hard-level simulation problems is choosing the right data structures. Once you map "finding the closest available ID" to a Binary Search Tree / Set, and "finding the earliest completion time" to a Min-Heap, the implementation flows naturally.
