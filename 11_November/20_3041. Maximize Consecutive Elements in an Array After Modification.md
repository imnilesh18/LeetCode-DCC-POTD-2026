## 📋 Problem Statement

You are given a **0-indexed** array `nums` consisting of positive integers.

Initially, you can increase the value of **any** element in the array by **at most `1`** (meaning for each element independently, you may choose either to add `1` or leave it unchanged).

After that, you need to select **one or more** elements from the final array such that those elements are **consecutive** when sorted in increasing order. For example, the elements `[3, 4, 5]` are consecutive, while `[3, 4, 6]` and `[1, 1, 2, 3]` are not.

Return the **maximum** number of elements that you can select.

---

## 🔒 Constraints

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^6$

## 💡 Approach

### 1. Order Independence & Sorting
Because we can select elements from any indices in `nums` and sort them afterward to check if they are consecutive, the original ordering of `nums` does not matter. Sorting `nums` in non-decreasing order first guarantees that valid next elements always appear to the right (`j > i`) and allows us to locate target values in **$O(\log n)$** time using Binary Search (`lower_bound`).

### 2. Exploring Every Starting Point & Initial State
Since the optimal consecutive sequence can begin with any element in the array, we iterate over every index `i` (`0 <= i < n`) as a potential starting point. At index `i`, we have two choices for its initial modification (`inc`):
- **No Increment (`inc = 0`):** `currVal = nums[i] + 0`
- **Increment by 1 (`inc = 1`):** `currVal = nums[i] + 1`

### 3. Two Transitions to Form `currVal + 1`
Once the current value `currVal` at index `i` is fixed, the very next number in our consecutive chain must equal `currVal + 1`. Searching strictly to the right (`start = i + 1`), there are two ways to obtain `currVal + 1`:
1. **Option 1 (Direct Match):** Find an existing element equal to `currVal + 1` at some index `j > i` and use it **without** incrementing it (`inc = 0` at `j`).
2. **Option 2 (Incremented Match):** Find an existing element equal to `currVal` at some index `j > i` and **increment** it by `+1` (`inc = 1` at `j`) so that it becomes `currVal + 1`.

> **Why explore both options?** Consider sorted `nums = [1, 1, 2, ...]`. Standing at index `0` (`currVal = 1`), we need `2`. If we pick the existing `2` at index `2` (Option 1), we cannot reach `3` afterward. Instead, if we pick the duplicate `1` at index `1` and increment it to `2` (Option 2), we can subsequently pick the `2` at index `2` and increment it to `3`, forming `[1, 2, 3]`.

### 4. Logarithmic Lookup via `lower_bound`
In `findMethod(nums, start, target)`, we use `lower_bound` starting from `nums.begin() + start` to locate the first element $\ge \text{target}$. Since `lower_bound` returns an iterator to the first element greater than or equal to `target`, we check `j < n && nums[j] == target` to confirm an exact match; otherwise, we return `-1`.

### 5. Top-Down DP (Memoization) $\rightarrow$ Bottom-Up DP (Tabulation)
- **Top-Down DP:** The recursive state `solve(i, inc, nums)` depends solely on two parameters: `i` ($0 \le i < n$) and `inc` ($\{0, 1\}$). Caching results in a 2D table `memo[n + 1][2]` prevents redundant work, achieving $O(n \log n)$ time.
- **Bottom-Up DP:** Since `dp[i][inc]` relies only on future indices `j >= i + 1`, we eliminate recursion overhead by iterating `i` backward from `n - 1` down to `0` and `inc` from `0` to `1`, updating `result` on the fly.

## 💻 Solution Code

### Approach 1: Top-Down DP (Recursion + Memoization)

```cpp
// Intuition: Sorting allows consecutive elements to be found from left to right using binary search. At each element, we can either leave it as is (+0) or increment it (+1), and recursively extend the chain by finding the next consecutive value.
// Approach:
// 1. Sort the input array nums in ascending order.
// 2. For every index i and initial increment inc (0 or 1), compute currVal = nums[i] + inc.
// 3. Use binary search (lower_bound) from i + 1 to find either (currVal + 1) with 0 increment, or (currVal) with +1 increment.
// 4. Memoize subproblem results in a 2D table memo[n + 1][2] and return the maximum sequence length across all starting states.
// Time Complexity: O(n log n) — Sorting takes O(n log n), and there are 2 * n DP states, each performing at most two O(log n) binary searches.
// Space Complexity: O(n) — Uses O(n) space for the 2D memoization table and O(n) auxiliary recursion call stack space.

//Approach-1 (Recursion Memoization)
//T.C : O(nlogn)
//S.C : O(n)
class Solution {
public:
    int n;
    vector<vector<int>> memo;

    // Binary search for exact match of target starting from index 'start'
    int findMethod(vector<int>& nums, int start, int target) {
        int j = lower_bound(begin(nums) + start, end(nums), target) - begin(nums);

        if(j < n && nums[j] == target) {
            return j;
        }

        return -1;
    }

    int solve(int i, int inc, vector<int>& nums) {

        // Return cached result if state (i, inc) is already computed
        if(memo[i][inc] != -1) {
            return memo[i][inc];
        }

        int currVal = nums[i] + inc; //inc = 0/1 (current value after applying increment)
        int len = 1;                 // Minimum consecutive chain length starting here is 1

        //1st Option = find (currVal+1) directly without incrementing it
        int j = findMethod(nums, i+1, currVal+1);
        if(j != -1) {
            len = max(len, 1 + solve(j, 0, nums));
        }

        //2nd Option = find (currVal) and then inc by +1 to form (currVal+1)
        j = findMethod(nums, i+1, currVal);
        if(j != -1) {
            len = max(len, 1 + solve(j, 1, nums));
        }

        return memo[i][inc] = len;
    }

    int maxSelectedElements(vector<int>& nums) {
        n = nums.size();

        // Sort array so next consecutive candidates always appear at indices > i
        sort(begin(nums), end(nums));

        memo.assign(n+1, vector<int>(2, -1));

        int result = 1;
        // Try starting the consecutive sequence from every index with +0 or +1
        for(int i = 0; i < n; i++) {
            result = max({result, solve(i, 0, nums), solve(i, 1, nums)});
        }

        return result;
    }
};

/*
*
* Dry Run
*
* Input: nums = [2, 1, 5, 1, 1]
* After sorting: nums = [1, 1, 1, 2, 5], n = 5
*
* Start at i = 0, inc = 0:
* currVal = nums[0] + 0 = 1, len = 1
* Option 1: findMethod(nums, 1, 2) returns j = 3 -> calls solve(3, 0)
*   In solve(3, 0): currVal = 2 + 0 = 2, neither 3 nor 2 exists after index 3 -> returns 1
*   len becomes max(1, 1 + 1) = 2
* Option 2: findMethod(nums, 1, 1) returns j = 1 -> calls solve(1, 1)
*   In solve(1, 1): currVal = 1 + 1 = 2
*     Option 1: findMethod(nums, 2, 3) returns -1
*     Option 2: findMethod(nums, 2, 2) returns j = 3 -> calls solve(3, 1)
*       In solve(3, 1): currVal = 2 + 1 = 3, neither 4 nor 3 exists after index 3 -> returns 1
*     solve(1, 1) returns 1 + 1 = 2
*   len becomes max(2, 1 + 2) = 3
*
* memo[0][0] = 3, result is updated to 3
* All other starting states yield lengths <= 3
* Final Output: 3
*
*/

```

### Approach 2: Bottom-Up DP (Iterative Tabulation — Optimal)

```cpp
// Intuition: Since every recursive transition from index i jumps strictly forward to some index j >= i + 1, we can compute DP states iteratively in reverse order from right to left without recursion stack overhead.
// Approach:
// 1. Sort nums in non-decreasing order and initialize a 2D DP table dp[n + 1][2] with 0.
// 2. Iterate index i backward from n - 1 down to 0, and inc from 0 to 1.
// 3. Compute currVal = nums[i] + inc, then query findMethod from i + 1 for (currVal + 1) using dp[j][0] and (currVal) using dp[j][1].
// 4. Store the best length in dp[i][inc] and track the global maximum in result on the fly.
// Time Complexity: O(n log n) — Sorting takes O(n log n), and the reverse loop executes 2 * n iterations with two O(log n) binary searches each.
// Space Complexity: O(n) — Uses O(n) memory for the 2D DP table and eliminates O(n) recursion stack space.

//Approach-2 (Bottom Up)
//T.C : O(nlogn)
//S.C : O(n)
class Solution {
public:
    vector<vector<int>> dp;
    int n;

    // Binary search for exact match of target starting from index 'start'
    int findMethod(vector<int>& nums, int start, int target) {
        int j = lower_bound(nums.begin() + start, nums.end(), target) - nums.begin();
        if (j < n && nums[j] == target)
            return j;

        return -1;
    }

    int maxSelectedElements(vector<int>& nums) {
        // Sort nums to enable O(log n) binary search for next consecutive elements
        sort(nums.begin(), nums.end());
        n = nums.size();
        dp.assign(n + 1, vector<int>(2, 0));

        int result = 1;

        // Fill DP table from right to left since states depend on future indices j > i
        for (int i = n - 1; i >= 0; i--) { //O(n * log(n))
            for (int inc = 0; inc <= 1; inc++) {

                int currVal = nums[i] + inc;
                int len = 1;

                //1st Option = find (currVal+1) directly without incrementing
                int j = findMethod(nums, i + 1, currVal + 1);
                if (j != -1) {
                    len = max(len, 1 + dp[j][0]);
                }

                //2nd Option = find (currVal) and then inc by +1
                j = findMethod(nums, i + 1, currVal);
                if (j != -1) {
                    len = max(len, 1 + dp[j][1]);
                }

                dp[i][inc] = len;
                result = max(result, len); // Track maximum chain length on the fly
            }
        }

        return result;
    }
};

/*
*
* Dry Run
*
* Input: nums = [2, 1, 5, 1, 1]
* After sorting: nums = [1, 1, 1, 2, 5], n = 5
*
* i = 4 (nums[4] = 5):
*   inc = 0: currVal = 5 -> no 6 or 5 after index 4 -> dp[4][0] = 1, result = 1
*   inc = 1: currVal = 6 -> no 7 or 6 after index 4 -> dp[4][1] = 1, result = 1
*
* i = 3 (nums[3] = 2):
*   inc = 0: currVal = 2 -> no 3 or 2 after index 3 -> dp[3][0] = 1, result = 1
*   inc = 1: currVal = 3 -> no 4 or 3 after index 3 -> dp[3][1] = 1, result = 1
*
* i = 2 (nums[2] = 1):
*   inc = 0: currVal = 1 -> finds 2 at j = 3 -> dp[2][0] = 1 + dp[3][0] = 2, result = 2
*   inc = 1: currVal = 2 -> finds 2 at j = 3 -> dp[2][1] = 1 + dp[3][1] = 2, result = 2
*
* i = 1 (nums[1] = 1):
*   inc = 0: currVal = 1 -> Option 1 finds 2 at j = 3 (len = 2); Option 2 finds 1 at j = 2 -> 1 + dp[2][1] = 3 -> dp[1][0] = 3, result = 3
*   inc = 1: currVal = 2 -> Option 2 finds 2 at j = 3 -> dp[1][1] = 1 + dp[3][1] = 2, result = 3
*
* i = 0 (nums[0] = 1):
*   inc = 0: currVal = 1 -> Option 1 finds 2 at j = 3 (len = 2); Option 2 finds 1 at j = 1 -> 1 + dp[1][1] = 3 -> dp[0][0] = 3, result = 3
*   inc = 1: currVal = 2 -> Option 2 finds 2 at j = 3 -> dp[0][1] = 1 + dp[3][1] = 2, result = 3
*
* Final Output: 3
*
*/

```

## 📝 Notes

* **Why `lower_bound` Always Picks the Earliest Occurrence:** Because `nums` is sorted in non-decreasing order, picking the *first* (leftmost) index `j > i` that matches `target` leaves the maximum possible number of elements remaining to the right (`> j`) to extend the sequence further.


* **Exact Match Verification:** `std::lower_bound` returns the first element that is **greater than or equal to** `target`, so checking `j < n && nums[j] == target` is mandatory to avoid false matches.


* **No Out-of-Bounds Check Needed in `solve`:** In Approach 1, recursive calls `solve(j, ...)` are only triggered when `findMethod` returns a valid index `j != -1` (`0 <= j < n`), ensuring `i` is always in bounds.



---

## 🔑 Key Insights

* **State Compression via Binary Search:** Instead of tracking the previous value $V$ directly as a DP state (which would range up to $10^6 + 1$), representing the state by `(index, inc)` reduces the state space from $O(\max(\text{nums}))$ to strictly $2n$ states.


* **Handling Duplicate Elements:** Duplicate values in `nums` are the exact reason `+1` modifications are powerful—one copy of `x` can remain `x` while another copy of `x` becomes `x + 1`.


* **Alternative $O(n \log n)$ Hash/Array DP Perspective:** Since each element `x` can become `x` or `x + 1`, one can also maintain `dp[v]` = longest consecutive sequence ending at value `v`. Processing sorted `nums` from left to right gives `dp[x + 1] = dp[x] + 1` and `dp[x] = dp[x - 1] + 1` (evaluated in that order so `x` does not chain onto itself within the same element).
