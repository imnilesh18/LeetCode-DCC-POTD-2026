## 📋 Problem Statement

Given an array of integers `arr`, return *the number of subarrays with an **odd** sum* .

Since the answer can be very large, return it modulo $10^9 + 7$ .

- **Problem Link:** [1524. Number of Sub-arrays With Odd Sum](https://leetcode.com/problems/number-of-sub-arrays-with-odd-sum/description/) 
- **Difficulty:** `Medium` 

---

## 🔒 Constraints

- $1 \le \text{arr.length} \le 10^5$ 
- $1 \le \text{arr}[i] \le 100$

| **Example 3** | `[1, 2, 3, 4, 5, 6, 7]` | `16` | Out of all $28$ possible subarrays, exactly `16` subarrays yield an odd sum . |

## 💡 Approach

Great code rarely emerges fully formed on the first attempt—it evolves iteratively from a straightforward brute-force draft to a refined optimal solution . Below is the complete progression from $O(n^3)$ down to $O(n)$ time and $O(1)$ auxiliary space .

### 1. Brute Force ($O(n^3)$ Time, $O(1)$ Space)
- Fix a starting index `i` from `0` to `n - 1` and an ending index `j` from `i` to `n - 1` .
- Use a third inner loop `k` from `i` to `j` to compute the subarray sum from scratch .
- Check if `sum % 2 != 0`; if true, increment `count` .
- **Limitation:** With $n \le 10^5$, an $O(n^3)$ algorithm performs up to $\approx 1.6 \times 10^{14}$ operations and results in **Time Limit Exceeded (TLE)** .

### 2. Better Brute Force ($O(n^2)$ Time, $O(1)$ Space)
- Notice that when moving the ending pointer `j` forward for a fixed `i`, recalculating the sum from `i` to `j` repeats prior work .
- By maintaining a running `sum` inside the `i` loop and simply adding `arr[j]` at each step, we eliminate the innermost `k` loop .
- **Limitation:** While much cleaner, $O(n^2)$ still executes $\approx 5 \times 10^9$ operations for $n = 10^5$, which triggers **TLE** .

### 3. Optimal Prefix Sum & Parity Tracking ($O(n)$ Time, $O(n)$ Space)

#### Connecting to Prior Prefix Sum Problems
Consider classic prefix sum problems such as *Subarray Sum Equals 0*, *Subarray Sum Equals K* (LeetCode 560), and *Subarray Sums Divisible by K* . In *Subarray Sum Equals 0*, if the cumulative sum at index `1` is `10` and later reappears as `10` at index `4`, the intermediate subarray from index `2` to `4` must sum to `0` (`10 + 0 = 10`) .

#### Adapting to Odd/Even Parity
Instead of tracking exact prefix sum values, we track their **parity** (`even` vs. `odd`) using two fundamental arithmetic rules :

| Previous Prefix Sum Parity | Subarray Sum Parity Needed | Current Prefix Sum Parity | Formula |
| :---: | :---: | :---: | :--- |
| **Even** | **Odd** | **Odd** | $\text{Even} + \text{Odd} = \text{Odd}$  |
| **Odd** | **Odd** | **Even** | $\text{Odd} + \text{Even} = \text{Odd}$  |

1. **When `prefix[i]` is Even:** To end an odd-sum subarray at index `i`, we must subtract a previously seen **odd** prefix sum ($\text{Even} - \text{Odd} = \text{Odd}$) . Every prior odd prefix sum pairs with index `i` to form a valid odd subarray . Thus, we add `odd` to `count` and increment `even` .
2. **When `prefix[i]` is Odd:** To end an odd-sum subarray at index `i`, we must subtract a previously seen **even** prefix sum ($\text{Odd} - \text{Even} = \text{Odd}$) . Every prior even prefix sum pairs with index `i` to form a valid odd subarray . Thus, we add `even` to `count` and increment `odd` .

#### Why Initialize `even = 1`?
Before processing index `0`, the empty prefix sum is `0`, which is an **even** number . Initializing `even = 1` ensures that whenever `prefix[i]` itself is odd, the entire prefix subarray `arr[0...i]` (excluding nothing before it) is properly counted as a standalone odd-sum subarray .

### 4. Optimal Space-Optimized ($O(n)$ Time, $O(1)$ Space)
- In Approach 3, `prefix[i]` is only accessed once during iteration `i` and never referenced again .
- Replacing the `prefix` vector with a single running `sum` variable preserves identical logic while reducing auxiliary memory from $O(n)$ to $O(1)$ .

## 💻 Solution Code

### 1. Brute Force Approach

```cpp
// Intuition: Generate every possible subarray and check whether its total sum is odd.
// Approach: Use two nested loops to fix subarray boundaries (i, j) and a third inner loop (k) to compute the sum, incrementing count whenever sum % 2 != 0.
// Time Complexity: O(n^3) - Three nested loops iterate over all O(n^2) subarrays and sum up to n elements each.
// Space Complexity: O(1) - Only constant extra variables are used.

//Approach-1 (Brute Force)
//T.C : O(n^3)
//S.C : O(1)
class Solution {
public:
    const int M = 1e9 + 7; // Modulo constant to prevent overflow
    int numOfSubarrays(vector<int>& arr) {
        int n = arr.size();
        int count = 0;
        
        for (int i = 0; i < n; i++) { // Fix starting index of subarray
            for (int j = i; j < n; j++) { // Fix ending index of subarray
                int sum = 0;
                for (int k = i; k <= j; k++) { // Calculate sum from i to j
                    sum += arr[k];
                }
                if (sum % 2 != 0) { // Check if subarray sum is odd
                    count++;
                }
            }
        }
        
        return count % M; // Return final count modulo 1e9 + 7
    }
};

/*
 *
 * Dry Run
 *
 * Input: arr = [1, 3, 5], n = 3
 * i = 0, j = 0: k = 0 -> sum = 1 (odd) -> count = 1
 * i = 0, j = 1: k = 0..1 -> sum = 4 (even) -> count = 1
 * i = 0, j = 2: k = 0..2 -> sum = 9 (odd) -> count = 2
 * i = 1, j = 1: k = 1 -> sum = 3 (odd) -> count = 3
 * i = 1, j = 2: k = 1..2 -> sum = 8 (even) -> count = 3
 * i = 2, j = 2: k = 2 -> sum = 5 (odd) -> count = 4
 * Final Output: 4
 *
 */
```

### 2. Better Brute Force Approach

```cpp
// Intuition: Avoid recomputing overlapping subarray sums by maintaining a running sum as the end pointer advances.
// Approach: Fix starting index i, initialize sum = 0, and expand ending index j while accumulating arr[j] and checking parity at each step.
// Time Complexity: O(n^2) - Two nested loops examine every subarray in constant time per extension.
// Space Complexity: O(1) - Uses only scalar variables without auxiliary data structures.

//Approach-2 (Better Brute Force)
//T.C : O(n^2)
//S.C : O(1)
class Solution {
public:
    const int M = 1e9 + 7; // Modulo constant for large answers
    int numOfSubarrays(vector<int>& arr) {
        int n = arr.size();
        int count = 0;
        
        for (int i = 0; i < n; i++) { // Fix starting index i
            int sum = 0; // Reset running sum for new start index
            for (int j = i; j < n; j++) { // Extend ending index j
                sum += arr[j]; // Accumulate current element
                if (sum % 2 != 0) { // Increment count if running sum is odd
                    count = (count+1)%M;
                }
            }
        }
        
        return count % M;
    }
};

/*
 *
 * Dry Run
 *
 * Input: arr = [1, 3, 5], n = 3
 * i = 0: sum = 0
 *   j = 0 -> sum = 1 (odd) -> count = 1
 *   j = 1 -> sum = 4 (even) -> count = 1
 *   j = 2 -> sum = 9 (odd) -> count = 2
 * i = 1: sum = 0
 *   j = 1 -> sum = 3 (odd) -> count = 3
 *   j = 2 -> sum = 8 (even) -> count = 3
 * i = 2: sum = 0
 *   j = 2 -> sum = 5 (odd) -> count = 4
 * Final Output: 4
 *
 */
```

### 3. Optimal Approach (Prefix Sum Array)

```cpp
// Intuition: A subarray sum is odd if and only if the prefix sums at its boundaries have opposite parities (even + odd = odd, odd + even = odd).
// Approach: Precompute the prefix sum array, initialize even = 1 (for empty prefix sum 0) and odd = 0, then iterate through prefix sums to pair each prefix with prior opposite-parity prefixes.
// Time Complexity: O(n) - One pass to build the prefix array and one pass to count odd-sum subarrays.
// Space Complexity: O(n) - Extra vector of size n stores the cumulative prefix sums.

//Approach-3 (Optimal using prefix-sum array)
//T.C : O(n)
//S.C : O(n)
class Solution {
public:
    int M = 1e9+7;
    int numOfSubarrays(vector<int>& arr) {
        int n = arr.size();

        vector<int> prefix(n, 0); // Store cumulative sums up to each index
        prefix[0] = arr[0];

        for(int i = 1; i < n; i++) { // Build prefix sum array
            prefix[i] = prefix[i-1] + arr[i];
        }

        int count = 0;
        int odd = 0; // Count of odd prefix sums seen so far
        int even = 1; // Count of even prefix sums seen so far (includes initial 0)

        for(int i = 0; i < n; i++) {
            if(prefix[i]%2 == 0) { // Even prefix needs prior odd prefix: odd + even = odd
                count = (count + odd) % M;
                even++;
            } else { // Odd prefix needs prior even prefix: even + odd = odd
                count = (count + even) % M;
                odd++;
            }
        }

        return count;
    }
};

/*
 *
 * Dry Run
 *
 * Input: arr = [1, 3, 5]
 * prefix = [1, 4, 9]
 * Initial: count = 0, odd = 0, even = 1
 * i = 0: prefix[0] = 1 (odd) -> count = (0 + 1) % M = 1, odd = 1
 * i = 1: prefix[1] = 4 (even) -> count = (1 + 1) % M = 2, even = 2
 * i = 2: prefix[2] = 9 (odd) -> count = (2 + 2) % M = 4, odd = 2
 * Final Output: 4
 *
 */
```

### 4. Optimal Approach (Constant Space)

```cpp
// Intuition: Since we only ever need the current cumulative sum and the running counts of previous even and odd prefix sums, storing the entire prefix array is unnecessary.
// Approach: Maintain a single running sum variable alongside even = 1 and odd = 0 counters, updating the odd subarray count in one pass.
// Time Complexity: O(n) - Single linear scan through the input array.
// Space Complexity: O(1) - Eliminates the O(n) prefix array by using a single running sum variable.

//Approach-4 (Optimal using constant space)
//T.C : O(n)
//S.C : O(1)
class Solution {
public:
    int M = 1e9+7;
    int numOfSubarrays(vector<int>& arr) {
        int n = arr.size();

        int count = 0;
        int odd = 0; // Tracks number of odd prefix sums encountered
        int even = 1; // Tracks number of even prefix sums encountered (starts at 1 for sum = 0)
        int sum = 0; // Running cumulative prefix sum

        for(int i = 0; i < n; i++) {
            sum += arr[i]; // Update running prefix sum

            if(sum%2 == 0) { // Even sum pairs with all previous odd sums: odd + even = odd
                count = (count + odd) % M;
                even++;
            } else { // Odd sum pairs with all previous even sums: even + odd = odd
                count = (count + even) % M;
                odd++;
            }
        }

        return count;
    }
};

/*
 *
 * Dry Run
 *
 * Input: arr = [1, 3, 5]
 * Initial: count = 0, odd = 0, even = 1, sum = 0
 * i = 0: sum = 1 (odd) -> count = (0 + 1) % M = 1, odd = 1
 * i = 1: sum = 4 (even) -> count = (1 + 1) % M = 2, even = 2
 * i = 2: sum = 9 (odd) -> count = (2 + 2) % M = 4, odd = 2
 * Final Output: 4
 *
 */
```

## 📝 Notes

- **Integer Overflow Prevention:** For an array of length $n = 10^5$, the maximum possible number of subarrays is $\frac{n(n+1)}{2} = 5,000,050,000$, which exceeds the 32-bit signed integer limit ($2^{31} - 1 \approx 2.14 \times 10^9$) . Applying `% M` ($10^9 + 7$) during every addition guarantees `count` stays safely within 32-bit integer bounds .
- **Running Sum Bounds:** Since $n \le 10^5$ and $\text{arr}[i] \le 100$, the maximum cumulative `sum` is $10^5 \times 100 = 10^7$, which fits comfortably inside a standard 32-bit `int` without overflowing .
- **Negative Numbers Compatibility:** Note that if the input array were ever extended to include negative numbers, `sum % 2 == 0` in C++ still accurately identifies even numbers, whereas checking odd numbers should use `sum % 2 != 0` rather than `sum % 2 == 1` (since `-3 % 2 == -1` in C++).

---

## 🔑 Key Insights

- **Parity Reduction:** You never need the actual magnitude of subarray sums—only their remainder modulo `2` (`sum % 2`) .
- **Empty Prefix Seeding (`even = 1`):** Seeding `even = 1` represents the empty prefix sum `0` before index `0`, automatically accounting for every valid odd-sum subarray starting at index `0` without special-case branching .
- **State Compression:** Whenever a prefix-sum recurrence depends solely on aggregate counts of past states (like `even` and `odd` frequencies) rather than specific indices, an $O(n)$ prefix array can always be compressed into $O(1)$ space .
