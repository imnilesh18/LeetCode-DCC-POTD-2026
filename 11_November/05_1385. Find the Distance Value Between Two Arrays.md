# 1385. Find the Distance Value Between Two Arrays

**Difficulty:** Easy  
**Topics:** `Array`, `Two Pointers`, `Binary Search`, `Sorting`  
**Problem Link:** [LeetCode 1385](https://leetcode.com/problems/find-the-distance-value-between-two-arrays/description)

---

## 📜 Problem Statement

Given two integer arrays `arr1` and `arr2`, and the integer `d`, return the distance value between the two arrays.

The distance value is defined as the number of elements `arr1[i]` such that there is not any element `arr2[j]` where `|arr1[i] - arr2[j]| <= d`.

---

## ⚠️ Constraints

- `1 <= arr1.length, arr2.length <= 500`
- `-1000 <= arr1[i], arr2[j] <= 1000`
- `0 <= d <= 100`

---

## 🧠 Approach & Explanation

The problem asks us to find how many elements in `arr1` maintain an absolute difference strictly greater than `d` with *every* element in `arr2`. If we find even a single element in `arr2` whose absolute difference with our current `arr1[i]` is less than or equal to `d`, we must discard `arr1[i]`.

### Approach 1: Brute Force (Simulation)
The most straightforward approach is to simulate exactly what the problem statement says. We pick an element from `arr1`, iterate through all elements of `arr2`, and calculate the absolute difference. If we ever encounter a difference `<= d`, we immediately flag the element as invalid and move on. If we finish checking all elements in `arr2` and all differences were `> d`, we increment our answer counter. Since the array constraints are small (up to 500), an $O(M \times N)$ approach will pass comfortably.

### Approach 2: Optimized Binary Search
Instead of comparing `arr1[i]` with every single element in `arr2`, we can sort `arr2` first. Once `arr2` is sorted, we only need to check the elements in `arr2` that are numerically closest to `arr1[i]`. If the closest elements have a difference greater than `d`, then by definition, all other elements in the sorted array will have an even larger difference.

To do this, we use Binary Search (`lower_bound` in C++) to find the first element in `arr2` that is greater than or equal to `arr1[i]`. Let this element be at index `j`. 
We then only need to check two specific elements in `arr2`:
1. `arr2[j]`: The immediate element $\ge$ `arr1[i]`.
2. `arr2[j-1]`: The immediate element $<$ `arr1[i]`.

If the absolute difference between `arr1[i]` and both of these boundary elements is strictly greater than `d`, then `arr1[i]` is a valid candidate. We also handle edge cases where `arr1[i]` is smaller than all elements in `arr2` (check only `arr2[0]`) or larger than all elements (check only `arr2[n-1]`).

## 💻 Solution Code

### Brute Force Solution

```cpp
// Intuition: The problem requires us to find elements in arr1 that maintain a distance strictly greater than 'd' from all elements in arr2. We can simply check every pair.
// Approach: 
// 1. Iterate through each element 'num1' in arr1.
// 2. Iterate through each element 'num2' in arr2.
// 3. Check if the absolute difference is less than or equal to 'd'. If so, 'num1' is invalid.
// 4. If 'num1' remains valid after checking all elements in arr2, increment the count.
// Time Complexity: O(m * n) where m is the length of arr1 and n is the length of arr2.
// Space Complexity: O(1) as we are only using a few variables for counting.
class Solution {
public:
    int findTheDistanceValue(vector<int>& arr1, vector<int>& arr2, int d) {
        int count = 0; // Initialize valid element count

        for (int& num1 : arr1) { // Pick each element from arr1
            bool valid = true; // Assume current element is valid

            for (int& num2 : arr2) { // Compare with every element in arr2
                if(abs(num1 - num2) <= d) { // If condition fails
                    valid = false; // Mark as invalid
                    break; // No need to check further for this num1
                }
            }
            
            count += valid; // False = 0, True = 1
        }

        return count; // Return total valid elements
    }
};

/*
*
* Dry Run
* arr1 = [4,5,8], arr2 = [10,9,1,8], d = 2
* 
* num1 = 4:
* |4-10| = 6 > 2
* |4-9| = 5 > 2
* |4-1| = 3 > 2
* |4-8| = 4 > 2 -> Valid, count = 1
* 
* num1 = 5:
* |5-10| = 5 > 2
* |5-9| = 4 > 2
* |5-1| = 4 > 2
* |5-8| = 3 > 2 -> Valid, count = 2
* 
* num1 = 8:
* |8-10| = 2 <= 2 -> Invalid, break loop. count remains 2.
* 
* Final count = 2
*
*/

```

### Optimized Binary Search Solution

```cpp
// Intuition: Instead of checking all elements in arr2 for each element in arr1, we can sort arr2. This allows us to quickly find the closest elements to arr1[i] using binary search (lower_bound).
// Approach:
// 1. Sort the array arr2.
// 2. For each element in arr1, use lower_bound to find the first element in arr2 that is >= arr1[i] (index j).
// 3. If such an element exists, check if its distance from arr1[i] is > d.
// 4. Also, check the element just before it (at index j-1), as it is the largest element < arr1[i].
// 5. If both closest elements satisfy the distance condition > d, then all elements in arr2 satisfy it.
// Time Complexity: O((m + n) log n) where n is arr2 size (for sorting) and m is arr1 size (for binary search).
// Space Complexity: O(1) auxiliary space, assuming in-place sorting algorithms.
class Solution {
public:
    int findTheDistanceValue(vector<int>& arr1, vector<int>& arr2, int d) {
        sort(begin(arr2), end(arr2)); // Sort arr2 for binary search

        int count = 0; // Initialize valid element count
        int n = arr2.size(); // Store size of arr2

        for(int i = 0; i < arr1.size(); i++) { // Iterate through arr1
            // Find first element >= arr1[i]
            int j = lower_bound(begin(arr2), end(arr2), arr1[i]) - begin(arr2);

            if(j == 0) { // all elements are greater or equal to arr1[i]
                count += (arr2[0] - arr1[i]) > d; // Check only the first element
            } else if(j >= n) { // all elements are smaller than arr1[i]
                count += (arr1[i] - arr2[n-1]) > d; // Check only the last element
            } else { // Elements exist on both sides of arr1[i]
                // Check both the immediate greater/equal and immediate smaller elements
                count += (arr2[j] - arr1[i] > d) && (arr1[i] - arr2[j-1] > d);
            }
        }

        return count; // Return total valid elements
    }
};

/*
*
* Dry Run
* arr1 = [4,5,8], arr2 = [10,9,1,8], d = 2
* Sort arr2 -> [1,8,9,10]
* 
* i = 0, arr1[0] = 4:
* lower_bound(4) in [1,8,9,10] is index 1 (value 8)
* j = 1. Check arr2[1] -> |8-4| > 2 (True) AND arr2[0] -> |4-1| > 2 (True)
* Both valid. count = 1
* 
* i = 1, arr1[1] = 5:
* lower_bound(5) in [1,8,9,10] is index 1 (value 8)
* j = 1. Check arr2[1] -> |8-5| > 2 (True) AND arr2[0] -> |5-1| > 2 (True)
* Both valid. count = 2
* 
* i = 2, arr1[2] = 8:
* lower_bound(8) in [1,8,9,10] is index 1 (value 8)
* j = 1. Check arr2[1] -> |8-8| > 2 (False).
* Invalid. count remains 2
* 
* Final count = 2
*
*/

```

## 📌 Key Insights & Notes

* **Simulation vs. Optimization:** Always start by identifying if a brute force simulation will pass based on constraints. Since $500 \times 500 = 250,000$ operations, $O(M \times N)$ is perfectly acceptable for interviews or contests. However, pointing out the $O(M \log N)$ binary search optimization highlights strong problem-solving skills.
* **Why Check Neighbors in Binary Search?** In a sorted array, the elements with the minimum absolute difference from a target `X` will *always* be the numbers immediately surrounding `X` (the lower bound and the element right before the lower bound). Checking just those two is sufficient to guarantee the condition for the entire array.
