## 📝 Problem Statement

You are given an integer array `nums` of length `n` and an integer `k`[cite: 1]. 

For each index `i`, define its **instability score** as `max(nums[0..i]) - min(nums[i..n - 1])`[cite: 1].

In other words:
*   `max(nums[0..i])` is the largest value among the elements from index `0` to index `i`[cite: 1].
*   `min(nums[i..n - 1])` is the smallest value among the elements from index `i` to index `n - 1`[cite: 1].

An index `i` is called **stable** if its instability score is less than or equal to `k`[cite: 1].

**Goal:** Return the **smallest stable index**. If no such index exists, return `-1`[cite: 1].

---

## 🚫 Constraints

*   $1 \le \text{nums.length} \le 100$[cite: 1]
*   $0 \le \text{nums[i]} \le 10^9$[cite: 1]
*   $0 \le k \le 10^9$[cite: 1]

## 🧠 Approach & Explanation

The problem asks us to find the earliest index where the difference between the running maximum (from the left) and the running minimum (from the right) is at most `k`[cite: 1].

<details>
<summary><b>Method 1: Brute Force (Simulation)</b></summary>
<br>
The most straightforward approach is to blindly simulate the problem statement. For every index <code>i</code>, we can run a loop from <code>0</code> to <code>i</code> to find the maximum element, and another loop from <code>i</code> to <code>n-1</code> to find the minimum element[cite: 1]. We then subtract the minimum from the maximum. If the result is less than or equal to <code>k</code>, we immediately return <code>i</code> since we are looking for the smallest index[cite: 1]. Because we use nested loops, this approach takes $O(N^2)$ time[cite: 1].
</details>

<details>
<summary><b>Method 2: Optimized (Prefix Max & Suffix Min)</b></summary>
<br>
The brute force method recalculates the maximums and minimums redundantly. We can optimize this down to linear time by doing a little pre-processing:
<ol>
  <li><b>Suffix Minimums:</b> Create an array to store the minimum element from any given index <code>i</code> to the end of the array <code>n-1</code>. We populate this by iterating backwards (right to left)[cite: 1].</li>
  <li><b>Prefix Maximums:</b> Instead of a secondary array, we can iterate forward (left to right) and simply maintain a running maximum variable on the fly[cite: 1].</li>
  <li><b>Evaluation:</b> At every index <code>i</code> during our forward pass, our running maximum represents <code>max(nums[0..i])</code>, and our pre-processed array at <code>i</code> represents <code>min(nums[i..n-1])</code>. We just subtract the two and check the condition[cite: 1].</li>
</ol>
This drops our time complexity to $O(N)$ with a space tradeoff of $O(N)$[cite: 1].
</details>

## 💻 Solution Code

### 🐌 Brute-Force Solution (C++)

```cpp
// Intuition: Simulates the direct definition of instability score by computing max and min for every index using nested loops.
// Approach: Iterate i from 0 to n-1. Inside, loop 0 to i for max, and i to n-1 for min. Check if diff <= k.
// Time Complexity: O(N^2) as we traverse the array to find max and min for every single index.
// Space Complexity: O(1) because we only allocate a few variables for tracking values.
class Solution {
public:
    int firstStableIndex(vector<int>& nums, int k) {
        int n = nums.size();
        
        // Check every index as a potential stable index
        for (int i = 0; i < n; i++) {
            int maxEl = -1e9;
            int minEl = 1e9;
            
            // Find max from 0 to i
            for (int j = 0; j <= i; j++) {
                maxEl = max(maxEl, nums[j]);
            }
            
            // Find min from i to n-1
            for (int j = i; j < n; j++) {
                minEl = min(minEl, nums[j]);
            }
            
            // Check instability score condition
            if (maxEl - minEl <= k) {
                return i;
            }
        }
        
        return -1;
    }
};

/*
*
* Dry Run
* Input: nums = [3,2,1], k = 1
* i = 0 -> max(3) = 3, min(3,2,1) = 1 -> score = 2 (> 1)
* i = 1 -> max(3,2) = 3, min(2,1) = 1 -> score = 2 (> 1)
* i = 2 -> max(3,2,1) = 3, min(1) = 1 -> score = 2 (> 1)
* Result: -1 (No stable index found)
*
*/
```

### 🚀 Optimized Solution (C++)

```cpp
// Intuition: Calculating prefix max and suffix min repeatedly is redundant. We can pre-process suffix minimums and compute prefix maximums on the fly to solve this in linear time.
// Approach: 
// 1. Traverse right-to-left to build a `minFromIndex` array storing suffix minimums.
// 2. Traverse left-to-right maintaining a running maximum element.
// 3. For each index, if the running max minus the pre-calculated suffix min is <= k, return it.
// Time Complexity: O(N) since we perform two independent linear traversals over the array.
// Space Complexity: O(N) due to the auxiliary vector used to store suffix minimums.
class Solution {
public:
    int firstStableIndex(vector<int>& nums, int k) {
        int n = nums.size();

        // Array to hold the min element from index i to n-1
        vector<int> minFromIndex(n);
        int minEl = INT_MAX;
        
        // Pre-processing: calculate suffix mins right-to-left
        for(int i = n-1; i >= 0; i--) {
            minEl = min(minEl, nums[i]);
            minFromIndex[i] = minEl;
        }

        int maxEl = 0;
        
        // Single pass: calculate prefix max on the fly and verify
        for(int i = 0; i < n; i++) {
            maxEl = max(maxEl, nums[i]);

            // If condition met, return the first stable index
            if(maxEl - minFromIndex[i] <= k)
                return i;
        }
        
        return -1;
    }
};

/*
*
* Dry Run
* Input: nums = [5,0,1,4], k = 3
* Pre-processing (right to left):
* minFromIndex[3] = min(INT_MAX, 4) = 4
* minFromIndex[2] = min(4, 1) = 1
* minFromIndex[1] = min(1, 0) = 0
* minFromIndex[0] = min(0, 5) = 0
* minFromIndex array -> [0, 0, 1, 4]
* 
* Main Loop (left to right):
* i = 0 -> maxEl = max(0, 5) = 5. Score = 5 - 0 = 5 (Not <= 3)
* i = 1 -> maxEl = max(5, 0) = 5. Score = 5 - 0 = 5 (Not <= 3)
* i = 2 -> maxEl = max(5, 1) = 5. Score = 5 - 1 = 4 (Not <= 3)
* i = 3 -> maxEl = max(5, 4) = 5. Score = 5 - 4 = 1 (<= 3). Return 3.
* Result: 3
*
*/
```

## 📌 Notes & Key Insights
*   **On-the-Fly Tracking:** The core realization of the optimal solution is understanding that as we move our evaluating index `i` from left to right, we can carry our knowledge of the highest value seen so far without looping backwards[cite: 1].
*   **Lookaheads require Memory:** Because we cannot easily look ahead to the end of the array in $O(1)$ time without prior knowledge, investing $O(N)$ space in a pre-processed right-to-left array easily shaves off an entire magnitude of time complexity[cite: 1]. 
*   **Scaling:** The optimized logic remains exactly the same for larger constraint variants of this problem (e.g., $N = 10^5$), whereas the brute force $O(N^2)$ solution will yield a Time Limit Exceeded (TLE) error[cite: 1].
