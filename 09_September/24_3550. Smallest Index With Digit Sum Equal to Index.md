## 📝 Problem Statement

You are given an integer array `nums`.

Return the **smallest index** `i` such that the sum of the digits of `nums[i]` is equal to `i`. 

If no such index exists, return `-1`.

---

## 🚀 Constraints

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 1000`

## 🧠 Approach & Key Insights

While a standard left-to-right loop easily solves this problem, there is a hidden, highly optimized approach buried in the constraints:

1. **"Smallest Index" Requirement:** Because we iterate from left to right, the *first* index we find that matches the condition will inherently be the *smallest*. We can immediately return it without needing to collect minimums or keep searching.
2. **The Output Range Bound (The Secret):** The constraints state that $0 \le nums[i] \le 1000$. 
    - What is the maximum possible digit sum for *any* number up to 1000? 
    - For $1000$, the sum is $1$. 
    - For $999$, the sum is $9 + 9 + 9 = 27$.
    - The largest digit total you can ever compute is **$27$**.
3. **Optimizing to $O(1)$ Time:** The condition is `i == digit_sum(nums[i])`. Because `digit_sum` can never exceed $27$, an index $i \ge 28$ can **never** be the answer. We can safely cap our loop at `min(nums.size(), 28)`. This reduces the problem to $O(1)$ constant time execution, regardless of whether the array length is $100$ or $1,000,000$.

## 💻 Solution Code (Brute Force)

```cpp
// Intuition: To find the smallest index where the digit sum equals the index, we can iterate sequentially from left to right. Returning on the first match guarantees it's the smallest.
// Approach: 
// 1. Traverse the array from index 0 to nums.size() - 1.
// 2. For each element, peel off its digits using modulo and division to compute the sum.
// 3. Compare the computed sum to the current index.
// 4. Return the index immediately upon a match, or -1 if the loop finishes.
// Time Complexity: O(N) where N is the length of the array. The digit peel takes at most 4 steps (since values <= 1000), making it O(1) per element.
// Space Complexity: O(1) as we only use a few constant variables for summing.

class Solution {
public:
    int smallestIndex(const vector<int>& nums) {
        // Lambda to extract and sum digits of a given number
        auto getDigitSum = [](int num) {
            int sum = 0;

            // Peel digits from right to left
            while (num > 0) {
                sum += num % 10;
                num /= 10;
            }

            return sum;
        };

        // Left-to-right walk naturally minimizes the index
        for (int i = 0; i < nums.size(); ++i) {
            // Check equality condition
            if (getDigitSum(nums[i]) == i) {
                return i;
            }
        }

        // Return -1 if no answer exists
        return -1;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 10, 11]
* 
* i = 0: nums[0] = 1 -> getDigitSum(1) = 1. (1 != 0)
* i = 1: nums[1] = 10 -> getDigitSum(10) = 1. (1 == 1) -> Match Found!
* Return: 1
*
*/

```

## ⚡ Solution Code (Optimized)

```cpp
// Intuition: Since nums[i] is at most 1000, its max digit sum is 27 (from 999). Therefore, an index of 28 or higher can never equal any possible digit sum in this array. We can strictly cap our search.
// Approach:
// 1. Same left-to-right iteration, but we bound the loop limit.
// 2. The upper limit is min(nums.size(), 28).
// 3. Extract the digit sum and compare with the index.
// 4. Return the index on the first match, or -1 if exhausted.
// Time Complexity: O(1) because the loop will run a maximum of 28 times regardless of input size, taking strict constant time.
// Space Complexity: O(1) utilizing no auxiliary data structures.

class Solution {
public:
    int smallestIndex(const vector<int>& nums) {
        // Lambda to extract and sum digits of a given number
        auto getDigitSum = [](int num) {
            int sum = 0;

            // Peel digits from right to left
            while (num > 0) {
                sum += num % 10;
                num /= 10;
            }

            return sum;
        };

        // Cap the iteration at 28 (max possible digit sum for 999 is 27)
        int searchLimit = min((int)nums.size(), 28);
        
        for (int i = 0; i < searchLimit; ++i) {
            // Check equality condition
            if (getDigitSum(nums[i]) == i) {
                return i;
            }
        }

        // Return -1 if no answer exists within bounds
        return -1;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 2, 3]
* searchLimit = min(3, 28) = 3
* 
* i = 0: nums[0] = 1 -> sum = 1. (1 != 0)
* i = 1: nums[1] = 2 -> sum = 2. (2 != 1)
* i = 2: nums[2] = 3 -> sum = 3. (3 != 2)
* Loop ends.
* Return: -1
*
*/

```

## 🔍 Notes & Further Exploration

* **The "Output Range Bound" Pattern:** Whenever a problem asks you to find an index equal to a computed function (like a digit sum, check sum, or depth), find the upper bound of that function based on the input constraints. The answer is trapped inside the function's range, not just the array's length.
* By strictly reading constraints, a simple $O(N)$ lookup transforms into a blazingly fast $O(1)$ constant-time calculation.
