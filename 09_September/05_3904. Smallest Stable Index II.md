## 📜 Problem Statement

You are given an integer array `nums` of length `n` and an integer `k`.[cite: 1]

For each index `i`, define its **instability score** as `max(nums[0..i]) - min(nums[i..n - 1])`.[cite: 1]

In other words:
*   `max(nums[0..i])` is the largest value among the elements from index `0` to index `i`.[cite: 1]
*   `min(nums[i..n - 1])` is the smallest value among the elements from index `i` to index `n - 1`.[cite: 1]

An index `i` is called **stable** if its instability score is less than or equal to `k`.[cite: 1]

Return the *smallest stable index*. If no such index exists, return `-1`.[cite: 1]

---

## 🚧 Constraints

*   $1 \le \text{nums.length} \le 10^5$[cite: 1]
*   $0 \le \text{nums}[i] \le 10^9$[cite: 1]
*   $0 \le k \le 10^9$[cite: 1]

## 🧠 Approach

### 1. Brute Force Strategy (Simulation)
The naive approach is to strictly follow the problem description. For every index `i`, we can traverse from `0` to `i` to find the maximum element, and traverse from `i` to `n-1` to find the minimum element. We calculate the difference and return the first index where the difference is $\le k$. While this works for small constraints, it results in a Time Complexity of $\mathcal{O}(N^2)$, which will cause a Time Limit Exceeded (TLE) error for array sizes up to $10^5$. 

### 2. Optimized Strategy (Pre-computation / Prefix & Suffix Arrays)
To optimize to $\mathcal{O}(N)$, we need to avoid the repetitive inner loops. 
*   **Suffix Minimums:** Notice that when calculating the minimum from `i` to `n-1`, we are repeatedly looking at the same right-side elements. We can pre-process the array by traversing from right to left, tracking and storing the minimum element seen so far at each index in a `minFromIndex` array. 
*   **Prefix Maximums (On the fly):** As we iterate through the array from left to right to evaluate each index `i`, we can simply maintain a running maximum. 
*   **Evaluation:** At any index `i`, the instability score is calculated instantly using the running maximum and `minFromIndex[i]`. This reduces our work to two linear passes.

## 💻 Solution Code

### Brute-force Solution (C++)
```cpp
// Intuition: The most straightforward way is to calculate the instability score independently for each index by finding the maximum element to its left and the minimum element to its right.
// Approach: 
// 1. Iterate through each index `i` from 0 to n-1.
// 2. Use a nested loop to find the maximum element from 0 to `i`.
// 3. Use another nested loop to find the minimum element from `i` to n-1.
// 4. If the difference is <= k, return `i`.
// Time Complexity: O(N^2) due to nested traversals for each index. This will result in TLE for large inputs.
// Space Complexity: O(1) as we only use a few tracking variables.

class Solution {
public:
    int firstStableIndex(vector<int>& nums, int k) {
        int n = nums.size();
        
        // Iterate through all potential indices
        for (int i = 0; i < n; i++) {
            int maxEl = -1e9;
            
            // Calculate max from 0 to i
            for (int j = 0; j <= i; j++) {
                maxEl = max(maxEl, nums[j]);
            }
            
            int minEl = 1e9;
            
            // Calculate min from i to n-1
            for (int j = i; j < n; j++) {
                minEl = min(minEl, nums[j]);
            }
            
            // Check instability score condition
            if (maxEl - minEl <= k) {
                return i;
            }
        }
        
        // Return -1 if no stable index exists
        return -1;
    }
};

/*
*
* Dry Run
* Input: nums = [3,2,1], k = 1
* 
* i=0: maxEl[0..0] = 3. minEl[0..2] = 1. Diff = 3-1 = 2. (2 > 1)
* i=1: maxEl[0..1] = 3. minEl[1..2] = 1. Diff = 3-1 = 2. (2 > 1)
* i=2: maxEl[0..2] = 3. minEl[2..2] = 1. Diff = 3-1 = 2. (2 > 1)
* No valid index found -> Return -1.
*
*/
```

### Optimized Solution (C++)
```cpp
// Intuition: Calculating max and min for every index independently causes overlapping, redundant work. By pre-computing the minimums from the right and tracking the maximum from the left on-the-fly, we can reduce the time complexity from O(N^2) to O(N).
// Approach: 
// 1. Initialize a vector `minFromIndex` to store the smallest element from index `i` to the end.
// 2. Populate `minFromIndex` by traversing the array from right to left, keeping track of the minimum seen.
// 3. Initialize `maxEl` to track the running maximum from left to right.
// 4. Traverse the array left to right, updating `maxEl` and calculating the score using `minFromIndex[i]`.
// 5. If `maxEl - minFromIndex[i] <= k`, return `i` immediately.
// Time Complexity: O(N) where N is the number of elements in the array. We perform exactly two linear passes.
// Space Complexity: O(N) because we allocate the `minFromIndex` array to store suffix minimums.

class Solution {
public:
    int firstStableIndex(vector<int>& nums, int k) {
        int n = nums.size();

        // Array to store suffix minimums
        vector<int> minFromIndex(n);
        int minEl = INT_MAX;
        
        // Pre-processing: populate min elements from right to left
        for(int i = n-1; i >= 0; i--) {
            minEl = min(minEl, nums[i]);
            minFromIndex[i] = minEl;
        }

        int maxEl = 0;
        
        // Single pass to find the first stable index
        for(int i = 0; i < n; i++) {
            // Update running prefix maximum
            maxEl = max(maxEl, nums[i]);

            // Check the instability score constraint
            if(maxEl - minFromIndex[i] <= k)
                return i;
        }
        
        return -1;
    }
};

/*
*
* Dry Run
* Input: nums = [5,0,1,4], k = 3
* 
* 1. minFromIndex initialization (Right-to-Left):
*    i=3: nums[3]=4 -> minEl=4 -> minFromIndex=[_,_,_,4]
*    i=2: nums[2]=1 -> minEl=1 -> minFromIndex=[_,_,1,4]
*    i=1: nums[1]=0 -> minEl=0 -> minFromIndex=[_,0,1,4]
*    i=0: nums[0]=5 -> minEl=0 -> minFromIndex=[0,0,1,4]
* 
* 2. Evaluation (Left-to-Right) with maxEl=0:
*    i=0: nums=5 -> maxEl=5. Score = 5 - minFromIndex[0] = 5 - 0 = 5. (5 > 3)
*    i=1: nums=0 -> maxEl=5. Score = 5 - minFromIndex[1] = 5 - 0 = 5. (5 > 3)
*    i=2: nums=1 -> maxEl=5. Score = 5 - minFromIndex[2] = 5 - 1 = 4. (4 > 3)
*    i=3: nums=4 -> maxEl=5. Score = 5 - minFromIndex[3] = 5 - 4 = 1. (1 <= 3) -> Return 3.
* 
* Output: 3
*
*/
```

## 📝 Notes

*   This problem acts as a two-part sequence on LeetCode. Part I features constraints where $N \le 100$, allowing the $\mathcal{O}(N^2)$ brute-force solution to pass. Part II scales $N$ up to $10^5$, necessitating the $\mathcal{O}(N)$ optimized approach using suffix arrays.
*   By trading spatial efficiency (using $\mathcal{O}(N)$ extra space) for temporal efficiency, we dramatically reduce the execution time constraints on large inputs.

## 🔑 Key Insights

*   **Prefix/Suffix Processing:** Overlapping subarray problems (like checking `0..i` and `i..n-1`) are prime candidates for prefix and suffix arrays. 
*   **On-the-fly Tracking:** Since we evaluate the array from left to right, we do not need a separate prefix-maximum array. We can just maintain a single scalar variable (`maxEl`) to track the maximum on the fly, saving $\mathcal{O}(N)$ space while maintaining the $\mathcal{O}(N)$ time complexity.

## 🚀 Further Exploration

Can this be solved in $\mathcal{O}(N)$ Time and $\mathcal{O}(1)$ Space?
Generally, tracking a trailing suffix minimum requires traversing backward, whereas a prefix maximum requires traversing forward. A strict $\mathcal{O}(1)$ space solution would require evaluating both bounds concurrently without holding the full state, which is mathematically prohibitive for unstructured data. Therefore, the $\mathcal{O}(N)$ space complexity represents the optimal bounds for this specific constraint set.
