## 📝 Problem Statement

You are given an integer array `nums` and an integer `x`[cite: 1]. In one operation, you can either remove the leftmost or the rightmost element from the array `nums` and subtract its value from `x`[cite: 1]. Note that this modifies the array for future operations[cite: 1].

Return *the minimum number of operations to reduce `x` to exactly `0` if it is possible, otherwise, return `-1`*[cite: 1].

---

## 🚀 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [1,1,4,2,3]`, `x = 5`[cite: 1] | `2`[cite: 1] | The optimal solution is to remove the last two elements to reduce `x` to zero[cite: 1]. |
| **2** | `nums = [5,6,7,8,9]`, `x = 4`[cite: 1] | `-1`[cite: 1] | It is impossible to reduce `x` to zero. |
| **3** | `nums = [3,2,20,1,1,3]`, `x = 10`[cite: 1] | `5`[cite: 1] | The optimal solution is to remove the last three elements and the first two elements (5 operations in total) to reduce `x` to zero[cite: 1]. |

---

## 🧐 Constraints

- `1 <= nums.length <= 10^5`[cite: 1]
- `1 <= nums[i] <= 10^4`[cite: 1]
- `1 <= x <= 10^9`[cite: 1]

---

## 💡 Approach & Intuition

### 1. Brute Force (Recursion)
At every step, you have two choices: pick the leftmost element or pick the rightmost element[cite: 1]. We can use recursion to explore all possible combinations. We keep track of the minimum operations required to reach exactly `0`. However, since this explores $2^N$ possibilities, it will result in a Time Limit Exceeded (TLE) error for larger arrays[cite: 1].

### 2. Optimized Approach (Sliding Window / Prefix Sum)
Instead of looking at the edges and trying to minimize the elements picked, we can invert the problem[cite: 1]. 
If we need to remove elements from the ends that sum up to `x`, it means the **remaining elements in the middle** must form a continuous subarray whose sum is exactly `Total Sum - x`[cite: 1]. 
Therefore, to minimize the operations (elements removed from the ends), we need to **maximize the length** of this middle subarray[cite: 1]. We can efficiently find the longest subarray with a target sum using a prefix sum array and a Hash Map[cite: 1].

---

## 🔑 Key Insights

> **Inverse Thinking:** Finding the minimum edge elements that sum to `X` is mathematically equivalent to finding the maximum contiguous middle subarray that sums to `Total Array Sum - X`[cite: 1]. 

> **Hash Map for Prefix Sums:** By storing prefix sums and their indices in a map, we can check if a required remaining sum exists in $O(1)$ time, optimizing our search to a single pass[cite: 1].

### Brute Force Solution (Recursion - TLE)

```cpp
// Intuition: We have two choices at every step: either pick the leftmost element or the rightmost element. Exploring all paths gives the answer, but it's highly inefficient.
// Approach: Recursively pick the left element (i++) or the right element (j--). Subtract the chosen value from `remain`. If `remain` hits 0, update `minCount`. Prune paths where `remain < 0` or pointers cross.
// Time Complexity: O(2^n) - We branch into two possibilities at each step (take left or take right).
// Space Complexity: O(1) excluding Stack space - The auxiliary recursion stack can grow up to O(n) in the worst case.
//Approach-2 (Using Recursion) - You Can memoize it as well but it will still give TLE
//T.C : O(2^n) -  We take and skip each ith and jth index
//S.C : O(1) excluding Stack space
class Solution {
    int minCount;
public:
    void solve(vector<int>& nums, int remain, int count, int i, int j) {
        // Base case: target successfully reduced to exactly 0
        if (remain == 0) {
            minCount = min(minCount, count);
            return;
        }
        // Base case: overshoot, pointers cross, or current path is worse than minCount
        else if (remain < 0 || i > j || count >= minCount)
            return;
        else {
            // Pick left edge element
            solve(nums, remain - nums[i], count + 1, i + 1, j);
            // Pick right edge element
            solve(nums, remain - nums[j], count + 1, i, j - 1);
        }
    }
    
    int minOperations(vector<int>& nums, int x) {
        int n = nums.size();
        minCount = INT_MAX; // Initialize to maximum possible operations

        // Start recursion with full array bounds
        solve(nums, x, 0, 0, n-1);
        
        // If impossible to reduce to exactly 0, return -1
        if (minCount == INT_MAX) 
            return -1;
        
        return minCount;
    }
};

/*
*
* Dry Run
*
* nums = [1,1,4,2,3], x = 5
* Start: solve(nums, 5, count=0, i=0, j=4)
* 
* Option A (Pick Left: 1): remain=4, count=1. Next call: solve(nums, 4, 1, 1, 4)
* Option B (Pick Right: 3): remain=2, count=1. Next call: solve(nums, 2, 1, 0, 3)
* 
* Expanding Option B:
*   -> Pick Right (2): remain=0, count=2. Target met! minCount updates to 2.
*   
* All other recursive branches will either hit remain < 0 or count >= 2 and prune.
* Result: 2
* 
*/
```

### Optimized Solution (Prefix Sum + Hash Map)

```cpp
// Intuition: To minimize elements taken from the edges to sum to x, we must maximize the contiguous subarray in the middle that sums to (Total Sum - x).
// Approach: Calculate the target sum for the middle subarray (`restSum`). Iterate through the array keeping a running prefix sum. Check the hash map to see if `current_sum - restSum` has been seen before. If so, update the longest subarray length.
// Time Complexity: O(n) - We traverse the array exactly twice. Map lookups take O(1) time on average.
// Space Complexity: O(n) - A hash map is used to store up to 'n' prefix sum combinations.
//Using longest subarray Sum logic
//T.C : O(n)
//S.C : O(n)
class Solution {
public:
    int minOperations(vector<int>& nums, int x) {        
        int n    = nums.size();
        int sum  = 0;
        unordered_map<int, int> mp;
        
        // Base case initialization to handle full prefix matches
        mp[0] = -1;
        
        // Step 1: Calculate total sum and store prefix sums with their indices
        for(int i = 0; i<n; i++) {
            sum += nums[i];
            mp[sum] = i; 
        }
        
        // If total sum is less than x, it's impossible to reduce x to 0
        if(sum < x)
            return -1;
            
        int restSum  = sum-x; // The target sum for the maximum middle subarray
        int longest  = INT_MIN;
        sum = 0; // Reset sum for the second pass
        
        // Step 2: Find the longest subarray that sums to `restSum`
        for(int i = 0; i<n; i++) {
            sum += nums[i];
            
            // If we found a valid prefix, update the longest subarray length
            if(mp.count(sum-restSum)) {
                longest = max(longest, i-mp[sum-restSum]);
            }
        }
        
        // Final operations = total elements - length of longest subarray
        return longest==INT_MIN?-1:n-longest;
    }
};

/*
*
* Dry Run
*
* nums = [1,1,4,2,3], x = 5
* Step 1: Total sum = 11. 
* Target restSum = 11 - 5 = 6.
* 
* Step 2: mp state: {0: -1, 1: 0, 2: 1, 6: 2, 8: 3, 11: 4}
* Loop Iteration:
* i=0: sum=1. 1-6 = -5 (not in map)
* i=1: sum=2. 2-6 = -4 (not in map)
* i=2: sum=6. 6-6 = 0 (in map at -1). length = 2 - (-1) = 3. longest = max(-inf, 3) = 3.
* i=3: sum=8. 8-6 = 2 (in map at 1). length = 3 - 1 = 2. longest = max(3, 2) = 3.
* i=4: sum=11. 11-6 = 5 (not in map)
* 
* Final longest = 3. 
* Minimum Operations = n - longest = 5 - 3 = 2.
* Result = 2.
* 
*/
```

## 📝 Notes
* The Prefix Sum + Hash Map approach elegantly transforms a two-ended sequence problem into a standard single-contiguous-sequence problem[cite: 1].
* Ensure you handle the edge case where the total sum of the array is strictly less than `x` efficiently by returning `-1` early[cite: 1]. 
* Map initialization `mp[0] = -1` is crucial for subarrays that start precisely at the beginning (index 0)[cite: 1].
