## 🔗 Problem Link

**[3483. Unique 3-Digit Even Numbers](https://leetcode.com/problems/unique-3-digit-even-numbers/)**

## 📝 Problem Statement

You are given an array of digits called `digits`. Your task is to determine the number of distinct three-digit even numbers that can be formed using these digits.

**Note:** Each copy of a digit can only be used once per number, and there may not be leading zeros.

## 📊 Examples

| Example | Input | Output | Explanation |
| :---: | :--- | :--- | :--- |
| **1** | `digits = [1,2,3,4]` | `12` | The 12 distinct 3-digit even numbers that can be formed are 124, 132, 134, 142, 214, 234, 312, 314, 324, 342, 412, and 432. Note that 222 cannot be formed because there is only 1 copy of the digit 2. |
| **2** | `digits = [0,2,2]` | `2` | The only 3-digit even numbers that can be formed are 202 and 220. Note that the digit 2 can be used twice because it appears twice in the array. |
| **3** | `digits = [6,6,6]` | `1` | Only 666 can be formed. |
| **4** | `digits = [1,3,5]` | `0` | No even 3-digit numbers can be formed. |

## 🔐 Constraints

- `3 <= digits.length <= 10`
- `0 <= digits[i] <= 9`

## 💡 Approach

<details>
<summary><b>Click to view detailed walkthrough</b></summary>

1. **Frequency Mapping:** Since we are only dealing with digits from `0` to `9`, we can count the occurrences of each digit in the input array using a hash map or a fixed-size array of size 10.
2. **Fixed Loops (Hundreds, Tens, Ones):** Instead of generating permutations of the given array (which can have duplicates and complex logic), we iterate through all possible valid combinations of a 3-digit number.
3. **Hundreds Place (`i`):** Can be any digit from `1` to `9` (no leading zeros).
4. **Tens Place (`j`):** Can be any digit from `0` to `9`.
5. **Ones Place (`k`):** Since the number must be **even**, it can only be `0, 2, 4, 6, 8`.
6. **Validation:** For every generated combination, we check our frequency map to see if we have enough of those specific digits. We decrement the count when we "use" a digit, and increment it back (backtrack) once the inner loops finish.
7. **Counting:** If all three digits can be successfully placed, we increment our valid number counter.

</details>

## 💻 Solution Code (Optimized)

```cpp
// Intuition: Generating permutations handles duplicate array elements poorly. Instead, we can check all valid 3-digit even structures by simulating place values (hundreds, tens, ones) and verifying if we have the required digits in our frequency map.
// Approach: Build a frequency array for the digits. Use 3 nested loops: hundreds (1-9), tens (0-9), and ones (0,2,4,6,8). Decrement the frequency of a digit when used. If a valid 3-digit even number is formed, count it, then backtrack by restoring the digit frequencies.
// Time Complexity: O(N) where N is the length of digits. Building the map takes O(N). The nested loops run for a constant 9 * 10 * 5 = 450 iterations, making it O(1) for the main logic. Overall time is O(N).
// Space Complexity: O(1) auxiliary space, because the frequency array `mp` always requires exactly 10 elements regardless of input size.
class Solution {
public:
    int totalNumbers(vector<int>& digits) {
        int count = 0;
        // Map to store frequency of digits 0-9
        vector<int> mp(10, 0);

        // Populate frequency map
        for(int &digit : digits) {
            mp[digit]++;
        }

        // Hundreds place (no leading zero)
        for(int i = 1; i <= 9; i++) {
            if(mp[i] == 0) continue;
            mp[i]--; // Use digit
            
            // Tens place
            for(int j = 0; j <= 9; j++) {
                if(mp[j] == 0) continue;
                mp[j]--; // Use digit
                
                // Ones place (must be even)
                for(int k = 0; k <= 8; k += 2) {
                    if(mp[k] == 0) continue;
                    mp[k]--; // Use digit

                    // Valid 3-digit even number formed
                    int num = i*100 + j*10 + k;
                    count++;
                    
                    mp[k]++; // Backtrack ones
                }
                mp[j]++; // Backtrack tens
            }
            mp[i]++; // Backtrack hundreds
        }
        return count;
    }
};

/*
*
* Dry Run
* Input: digits = [2, 1, 3, 0]
* Freq Map: mp[0]=1, mp[1]=1, mp[2]=1, mp[3]=1
* i = 1 (mp[1]>0): Use 1. mp[1]=0
*   j = 0 (mp[0]>0): Use 0. mp[0]=0
*     k = 2 (mp[2]>0): Use 2. num = 102. count = 1. mp[2] restored.
*   j = 2 (mp[2]>0): Use 2. mp[2]=0
*     k = 0 (mp[0]>0): Use 0. num = 120. count = 2. mp[0] restored.
*   j = 3 (mp[3]>0): Use 3. mp[3]=0
*     k = 0 (mp[0]>0): Use 0. num = 130. count = 3. mp[0] restored.
*     k = 2 (mp[2]>0): Use 2. num = 132. count = 4. mp[2] restored.
* (Process continues for i=2, i=3 generating all valid even combos)
* Total unique count returned successfully.
*
*/
```

## 🔑 Key Insights

- Generating all combinations using standard permutations (`next_permutation`) can lead to Time Limit Exceeded (TLE) or require complex set data structures to remove duplicates.
- The enumeration method uses a constant bounding box (450 checks total), yielding exceptionally fast execution time.
- Standard backtracking principles seamlessly keep track of digit availability via the decrement-increment pattern in the frequency map.
