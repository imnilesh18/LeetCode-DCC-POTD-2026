## 📝 Problem Statement

You are given an integer array `nums` of length `n`, where `nums` is a permutation of the numbers in the range `[0..n - 1]`.

You may swap elements at indices `i` and `j` only if `nums[i] AND nums[j] == k`, where `AND` denotes the bitwise AND operation and `k` is a non-negative integer.

Return the maximum value of `k` such that the array can be sorted in non-decreasing order using any number of such swaps. If `nums` is already sorted, return `0`.

## ⚠️ Constraints

- `1 <= n == nums.length <= 10^5`
- `0 <= nums[i] <= n - 1`
- `nums` is a permutation of integers from `0` to `n - 1`.

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [0, 3, 2, 1]` | `1` | Choose `k = 1`. Swapping `nums[1] = 3` and `nums[3] = 1` is allowed since `3 AND 1 == 1`, resulting in a sorted permutation: `[0, 1, 2, 3]`. |
| **2** | `nums = [0, 1, 3, 2]` | `2` | Choose `k = 2`. Swapping `nums[2] = 3` and `nums[3] = 2` is allowed since `3 AND 2 == 2`, resulting in a sorted permutation: `[0, 1, 2, 3]`. |
| **3** | `nums = [3, 2, 1, 0]` | `0` | Only `k = 0` allows sorting since no greater `k` allows the required swaps. |

## 🧠 Approach

### Understanding the Bitwise AND Property
When taking the bitwise AND of two numbers, the resulting value will always be less than or equal to the smaller of the two numbers. Furthermore, for a bit to be set (1) in the result `k`, that specific bit **must** be set in both of the original numbers being operated on. 

### The Brute Force Idea
Initially, one might consider checking all possible pairs to see which ones yield an AND result equal to a potential `k`, and then checking if those valid swaps can route every misplaced element to its sorted position (using components/DSU). However, checking all pairs takes $O(N^2)$ time, which is too slow for $N = 10^5$. 

### The Optimized Observation
For an element to be swapped, it must have all the bits that are set in `k`. If an element `nums[i]` is not in its correct sorted position (i.e., `nums[i] != i`), it *must* participate in a swap to reach its final position. Therefore, every single misplaced number in the array must have all the set bits of our chosen `k`. 

To maximize `k` while ensuring all misplaced elements can still be swapped, `k` simply becomes the bitwise AND of all the misplaced numbers in the array. 

We can implement this by initializing `k` to a value where all bits are set (e.g., `-1`). We iterate through the array, and whenever we find an element not in its correct position (`nums[i] != i`), we apply the bitwise AND operation between `k` and that element. If the array is perfectly sorted from the beginning, no elements will be misplaced, and `k` will remain `-1`. In this edge case, we simply return `0` as per the problem requirements.

## 🚀 Optimized Solution (C++)

```cpp
// Intuition: The maximum K that allows all misplaced elements to be swapped must exclusively contain bits present in every misplaced element.
// Approach: Initialize K to -1 (all bits set). Iterate through the array, and update K by taking the bitwise AND of K with every misplaced element. If already sorted, return 0.
// Time Complexity: O(N), as we iterate through the given array exactly once.
// Space Complexity: O(1), as we only use a constant amount of extra space for the variable K.

class Solution {
public:
    int sortPermutation(vector<int>& nums) {
        int n = nums.size();

        // Initialize K with all bits set to 1
        int K = -1; 

        // Traverse the array to identify misplaced elements
        for(int i = 0; i < n; i++) {
            if(nums[i] != i) {
                // Accumulate common set bits of all misplaced numbers
                K = (K & nums[i]);
            }
        }

        // If K is unchanged, array is already sorted; otherwise return K
        return K == -1 ? 0 : K;
    }
};

/*
*
* Dry Run
*
* Input: nums = [0, 3, 2, 1]
* 
* Initialization:
* n = 4
* K = -1 (binary: ...11111111)
* 
* Loop Traversal:
* i = 0 | nums[0] = 0 | nums[0] == 0 -> Correct position, skip.
* i = 1 | nums[1] = 3 | nums[1] != 1 -> K = -1 & 3 = 3.
* i = 2 | nums[2] = 2 | nums[2] == 2 -> Correct position, skip.
* i = 3 | nums[3] = 1 | nums[3] != 3 -> K = 3 & 1 = 1.
* 
* Result:
* K = 1 (Since K != -1, return K)
* Output: 1
*
*/
```

## 🔍 Key Insights & Notes
- **Bit Destruction Property:** When applying the bitwise AND operation cumulatively across a set of numbers, bits can only be "destroyed" (turn to 0) or remain unchanged. A new set bit (1) can never be generated. 
- **Identifying the Condition:** Recognizing that `nums[i] != i` inherently flags the exact elements that *demand* mobility is the pivotal step in solving this problem in $O(N)$.
- **Further Exploration:** Try solving variants of this problem where operations are restricted to Bitwise OR or XOR to understand how the mathematical properties shift the grouping logic.
