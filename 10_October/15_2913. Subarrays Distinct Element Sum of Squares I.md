## 📜 Problem Statement

You are given a **0-indexed** integer array `nums`.

The **distinct count** of a subarray of `nums` is defined as:
> Let `nums[i..j]` be a subarray of `nums` consisting of all the indices from `i` to `j` such that `0 <= i <= j < nums.length`. Then the number of distinct values in `nums[i..j]` is called the distinct count of `nums[i..j]`.

Return the **sum of the squares** of distinct counts of all subarrays of `nums`.

*A subarray is a contiguous non-empty sequence of elements within an array.*

## ⚙️ Constraints

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

---

## 🧠 Approach

Since the constraints on the array length are relatively small (`N <= 100`), an $O(N^2)$ solution is perfectly optimal. 

We can systematically find all subarrays by using two nested loops:
1. The outer loop `i` selects the starting index of the subarray.
2. The inner loop `j` expands the subarray from `i` to the end of the array.
3. As we expand the subarray one element at a time, we use a Hash Set (`unordered_set` in C++) to keep track of the unique elements in the current window.
4. The size of the Hash Set instantly gives us the distinct count of the current subarray `nums[i..j]`. We square this size and accumulate it into our total sum.

---

## 🚀 Solution Code (Optimized Brute-Force)

```cpp
// Intuition: To find the distinct count for all subarrays, we can iterate through all possible starting and ending points. Using a hash set helps maintain the distinct elements efficiently as we expand the subarray.
// Approach: 
// 1. Initialize `totalSum` to 0 to store the final result.
// 2. Use an outer loop `i` to fix the starting point of the subarray.
// 3. For each starting point, initialize an empty `unordered_set` to track distinct elements.
// 4. Use an inner loop `j` to expand the subarray from `i` to the end of the array.
// 5. Insert the current element `nums[j]` into the set.
// 6. The distinct count is simply the size of the set. Add the square of this size to `totalSum`.
// 7. Return `totalSum` after evaluating all subarrays.
// Time Complexity: O(n^2), where n is the length of the array. We visit each subarray once and set insertion takes O(1) on average.
// Space Complexity: O(n), as the hash set can store up to n elements in the worst case (all unique elements).

class Solution {
public:
    int sumCounts(vector<int>& nums) {
        int n = nums.size();
        int totalSum = 0; // Accumulator for the final result
        
        // Iterate through all possible starting points of subarrays
        for (int i = 0; i < n; ++i) {
            unordered_set<int> distinctElements; // Tracks unique items in current window
            
            // Expand the subarray ending at j and count distinct elements
            for (int j = i; j < n; ++j) {
                distinctElements.insert(nums[j]); // Insert element (ignores duplicates)
                int count = distinctElements.size(); // Get current distinct count
                totalSum += count * count; // Add squared count to total
            }
        }
        
        return totalSum;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 2, 1]
* 
* Initialization: n = 3, totalSum = 0
* 
* Outer loop i = 0: set = {}
*   Inner loop j = 0: nums[0]=1, set={1}, size=1. totalSum += 1^2 => 1
*   Inner loop j = 1: nums[1]=2, set={1, 2}, size=2. totalSum += 2^2 => 1 + 4 = 5
*   Inner loop j = 2: nums[2]=1, set={1, 2}, size=2. totalSum += 2^2 => 5 + 4 = 9
* 
* Outer loop i = 1: set = {}
*   Inner loop j = 1: nums[1]=2, set={2}, size=1. totalSum += 1^2 => 9 + 1 = 10
*   Inner loop j = 2: nums[2]=1, set={2, 1}, size=2. totalSum += 2^2 => 10 + 4 = 14
* 
* Outer loop i = 2: set = {}
*   Inner loop j = 2: nums[2]=1, set={1}, size=1. totalSum += 1^2 => 14 + 1 = 15
* 
* End of loops. Final totalSum = 15. Return 15.
*
*/
```

## 🔑 Key Insights

- **Incremental State Building:** Instead of recalculating the number of distinct elements from scratch for every single subarray, we reuse the state from `nums[i..j-1]` to compute `nums[i..j]` in $O(1)$ time using a Hash Set.
- **Constraint Awareness:** The small constraint $N \le 100$ is a strong hint that an $O(N^2)$ algorithm is expected and optimal enough to easily pass all test cases.

## 🔎 Further Exploration & References

- **Advanced Topic:** For extremely large arrays ($N \le 10^5$), this problem becomes much harder (similar to *Subarrays Distinct Element Sum of Squares II*) and requires advanced data structures like a **Segment Tree** combined with a **Binary Indexed Tree (Fenwick Tree)** or a sweep-line algorithm to achieve $O(N \log N)$ complexity.
