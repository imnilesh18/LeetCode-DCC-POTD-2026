# 3942. Minimum Operations to Sort a Permutation

**Problem Link:** [Minimum Operations to Sort a Permutation](https://leetcode.com/problems/minimum-operations-to-sort-a-permutation/)
**Difficulty:** Medium
**Tags:** `Array`, `Sorting`, `Math`, `Simulation`

---

## 📝 Problem Statement

You are given an integer array `nums` of length `n`, where `nums` is a permutation of the integers from `0` to `n - 1`.

You may perform only the following operations:
1. **Reverse** the entire array.
2. **Rotate Left by One**: Move the first element to the end of the array, and rest elements to left by one position.

Return an integer denoting the minimum number of operations required to sort the array in increasing order. If it is not possible to sort the array using only the given operations, return `-1`.

### Constraints:
- `1 <= n == nums.length <= 10^5`
- `0 <= nums[i] <= n - 1`
- `nums` is a permutation of integers from `0` to `n - 1`.

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [0,2,1]` | `2` | Rotate Left by one: `[2, 1, 0]`. Reverse the array: `[0, 1, 2]`. Sorted in 2 operations. |
| **2** | `nums = [1,0,2]` | `2` | Reverse the array: `[2, 0, 1]`. Rotate Left by one: `[0, 1, 2]`. Sorted in 2 operations. |
| **3** | `nums = [2,0,1,3]` | `-1` | It is impossible to reach `[2, 0, 1, 3]`. Thus, the answer is `-1`. |

---

## 🧠 Approach

The problem limits us to two operations: reversing the array and rotating it left. Crucially, neither of these operations changes the relative neighbors of any element; they only change the starting point or the direction of traversal. 

This means the array can only be sorted if it originally forms a valid circular sequence. We have two valid states:
1. **Ascending Circular Order:** The array elements are contiguous and increasing (with modulo arithmetic to wrap around). Condition: `nums[i] == (nums[i-1] + 1) % n`.
2. **Descending Circular Order:** The array elements are contiguous but decreasing. Condition: `nums[i-1] == (nums[i] + 1) % n`.

**Execution Steps:**
1. Traverse the array to count how many adjacent pairs follow the ascending and descending rules. 
2. If the array is already perfectly sorted, return `0`.
3. If it is in an **Ascending Sequence** (`asc_count == n-1`), we check two ways to bring `0` to the front:
   - **Left Rotations:** Requires `n - nums[0]` operations.
   - **Right Rotations:** Since we can't rotate right directly, we simulate it by reversing, rotating left, and reversing again. This takes `nums.back() + 2` operations.
   - We take the minimum of these two.
4. If it is in a **Descending Sequence** (`dsc_count == n-1`), we *must* perform `1` mandatory reverse to make it ascending. After reversing:
   - Calculate left rotations needed.
   - Calculate simulated right rotations needed.
   - Take the minimum of these combinations.
5. If the array matches neither sequence type, it is in a "bad" random order and can never be sorted. Return `-1`.

## 💻 Solution Code

```cpp
// Intuition: The array can only be sorted if its elements maintain a circular contiguous sequence. The allowed operations (Reverse and Rotate Left) only change the array's starting point or its direction (ascending vs. descending). Any other random permutation cannot be sorted.
// Approach: 
// 1. Traverse the array to count adjacent pairs that follow an ascending circular pattern or a descending circular pattern.
// 2. If the array is already perfectly sorted, return 0.
// 3. If the array is in an ascending circular pattern, calculate the minimum operations between purely rotating left or simulating a right rotation (using reverses).
// 4. If the array is in a descending circular pattern, it requires one mandatory reverse to become ascending, followed by the minimum of left or right rotations.
// 5. If neither pattern matches for the entire array, return -1.
// Time Complexity: O(n) because we iterate through the array of size n exactly once to check the patterns.
// Space Complexity: O(1) as we only use a few integer variables for counting and calculations, requiring constant extra space.
class Solution {
public:
    int minOperations(vector<int>& nums) {
        int n = nums.size();

        int asc_count = 0;
        int dsc_count = 0;

        // Count adjacent elements following ascending or descending circular sequences
        for(int i = 1; i < n; i++) {
            asc_count += (nums[i] == (nums[i-1]+1)%n);
            dsc_count += (nums[i-1] == (nums[i]+1)%n);
        }

        // Check if array is already fully sorted
        if(asc_count == n-1 && nums[0] == 0) { //0, 1, 2, .... n-1
            return 0;
        }

        // Case 1: Array is in an ascending circular order
        if(asc_count == n-1) {
            int leftRot  = n - nums[0]; // Operations to purely rotate left
            int rightRot = 1 + (nums.back() + 1) + 1; // Operations to simulate right rotation via reverses
            return min(leftRot, rightRot);
        }

        // Case 2: Array is in a descending circular order
        if(dsc_count == n-1) {
            // Mandatory 1 Reverse + Left Rotations
            int leftRot = n-nums.back() + 1;

            // x Left Rotations + 1 Reverse (Simulating Right Rotation)
            int rightRot = (nums[0]+1)%n + 1;

            return min(leftRot, rightRot);
        }

        // Array is in an unsolvable random order
        return -1;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 0, 2]
* n = 3
* Loop i = 1: nums[1]=0, nums[0]=1. asc_count += (0 == (1+1)%3 -> 0==2 False 0). dsc_count += (1 == (0+1)%3 -> 1==1 True 1).
* Loop i = 2: nums[2]=2, nums[1]=0. asc_count += (2 == (0+1)%3 -> 2==1 False 0). dsc_count += (0 == (2+1)%3 -> 0==0 True 1).
* Final counts: asc_count = 0, dsc_count = 2 (which equals n-1).
* Matches descending case logic (dsc_count == 2).
* leftRot = 3 - nums.back() + 1 = 3 - 2 + 1 = 2.
* rightRot = (nums[0]+1)%3 + 1 = (1+1)%3 + 1 = 2 + 1 = 3.
* Return min(leftRot, rightRot) = min(2, 3) = 2. Output is 2.
*
*/
```

## 📌 Notes & Key Insights
- **Key Insight:** A right rotation is not provided natively, but it can be mathematically simulated by executing: `Reverse -> Rotate Left (x times) -> Reverse`.
- **Optimization:** Instead of simulating the arrays and tracking states, we mathematically deduce the number of operations based entirely on the front (`nums[0]`) and back (`nums.back()`) elements relative to the array length `n`.
