## 📝 Problem Statement

You are given a **0-indexed** integer array `nums` and a target element `target`.

A target index is an index `i` such that `nums[i] == target`.

Return a list of the target indices of `nums` after sorting `nums` in **non-decreasing** order. If there are no target indices, return an empty list. The returned list must be sorted in increasing order.

---

## 🛑 Constraints

- `1 <= nums.length <= 100`
- `1 <= nums[i], target <= 100`

## 🧠 Approach

### 1. Brute Force (Sorting)
The most straightforward approach is to follow exactly what the problem asks: sort the array and then iterate through it. While iterating, whenever we find an element equal to our `target`, we push its current index into our result array. Because the array is sorted, the resulting indices will automatically be in increasing order.

### 2. Optimized (Frequency Counting)
Sorting takes $O(N \log N)$ time. However, if we think about the target's final position in a sorted array, it strictly depends on two things:
1. How many elements are **strictly less** than the `target`? (This tells us the starting index of our target).
2. How many elements are **exactly equal** to the `target`? (This tells us how many indices we need to collect).

By iterating through the array just once, we can calculate these two counts (`count1` and `count2`). Once we have them, we know that in a sorted array, the target would occupy the indices from `count1` up to `count1 + count2 - 1`. This entirely eliminates the need for sorting, dropping our time complexity to $O(N)$.

## 💻 Solution Code

### Brute-force Solution (C++)

```cpp
// Intuition: The simplest way to solve this is to simulate the problem statement by sorting the array and finding the matching indices.
// Approach: 
// 1. Sort the given array in non-decreasing order.
// 2. Iterate through the array and check if the current element equals the target.
// 3. If it does, add the index to the result array.
// Time Complexity: O(n log n) due to the sorting step.
// Space Complexity: O(1) auxiliary space, ignoring the space required for the output array and sorting recursion stack.
class Solution {
public:
    vector<int> targetIndices(vector<int>& nums, int target) {
        int n = nums.size(); // Get the size of the array

        sort(begin(nums), end(nums)); // Sort the array
        
        vector<int> result;
        for(int i = 0; i < n; i++) { // Iterate through the sorted array
            if(nums[i] == target) {
                result.push_back(i); // Push index if it matches the target
            }
        }

        return result;
    }
};

/*
* Dry Run
*
* nums = [1,2,5,2,3], target = 2
* After sort: nums = [1,2,2,3,5]
* i=0, nums[0]=1 != 2
* i=1, nums[1]=2 == 2 -> result=[1]
* i=2, nums[2]=2 == 2 -> result=[1, 2]
* i=3, nums[3]=3 != 2
* i=4, nums[4]=5 != 2
* Return [1, 2]
*/
```

### Optimized Solution (C++)

```cpp
// Intuition: Since we only care about the target's final positions, we don't need to actually sort the array. We just need to know how many elements precede it and how many times it appears.
// Approach:
// 1. Iterate through the array to count elements strictly less than the target (count1) and elements equal to the target (count2).
// 2. The target will occupy indices from `count1` to `count1 + count2 - 1` in a sorted array.
// 3. Loop through this range and add the indices to the result.
// Time Complexity: O(n) as we only iterate the array once (or twice linearly).
// Space Complexity: O(1) since we only use two integer variables for counting.
class Solution {
public:
    vector<int> targetIndices(vector<int>& nums, int target) {
        
        int count1 = 0;  // Number of elements less than target
        int count2 = 0;  // Number of elements equal to target
        
        for (int &num : nums) { // Single pass to get both counts
            if (num < target) 
                count1++;
            else if(num == target)
                count2++;
        }

        vector<int> result;
        // Target indices start at count1 and end just before count1 + count2
        for(int i = count1; i < count1 + count2; i++) {
            result.push_back(i);
        }
        
        return result;
    }
};

/*
* Dry Run
*
* nums = [1,2,5,2,3], target = 2
* Initialize count1 = 0, count2 = 0
* num = 1 -> 1 < 2 -> count1 = 1
* num = 2 -> 2 == 2 -> count2 = 1
* num = 5 -> 5 > 2 -> ignore
* num = 2 -> 2 == 2 -> count2 = 2
* num = 3 -> 3 > 2 -> ignore
* count1 = 1, count2 = 2
* Loop i from 1 to (1+2-1) -> pushes 1, 2
* Return [1, 2]
*/
```

## 📌 Notes
- The brute-force solution is highly intuitive but sub-optimal due to the sorting overhead.
- In interviews, directly jumping to the $O(N \log N)$ solution is acceptable, but the interviewer will almost certainly ask you to optimize it, specifically testing if you can deduce the mathematical placement of elements without physically sorting them.

## 🗝️ Key Insights
The placement of any element in a sorted array is strictly governed by the number of elements smaller than it. By simply counting the smaller elements, we mathematically deduce the target's starting offset. By counting its occurrences, we deduce its exact span.
