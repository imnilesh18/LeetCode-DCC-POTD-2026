# 301. Remove Invalid Parentheses

**Problem Link:** [301. Remove Invalid Parentheses](https://leetcode.com/problems/remove-invalid-parentheses/description)  
**Problem Name:** Remove Invalid Parentheses  
**Difficulty:** Hard  
**Tags:** String, Backtracking, Breadth-First Search  
**Badges:** 🧠 Advanced Backtracking, 🚀 Optimization  

---

## 📝 Problem Statement

Given a string `s` that contains parentheses and letters, remove the minimum number of invalid parentheses to make the input string valid.

Return a list of **unique strings** that are valid with the minimum number of removals. You may return the answer in **any order**.

---

## ⛔ Constraints

- `1 <= s.length <= 25`
- `s` consists of lowercase English letters and parentheses `'('` and `')'`.
- There will be at most `20` parentheses in `s`.

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `s = "()())()"` | `["(())()","()()()"]` | We can remove either the second closing bracket or the third closing bracket to make the sequence valid. |
| **2** | `s = "(a)())()"` | `["(a())()","(a)()()"]` | Similar to Example 1, characters are ignored during validation but retained in the final strings. |
| **3** | `s = ")("` | `[""]` | It is impossible to form a valid sequence, so removing both parentheses results in an empty string. |

---

## 📖 Explanation

The goal is to remove the absolute minimum number of parentheses required to form a balanced string, returning all unique possibilities. 

Since the constraints state a maximum of 20 parentheses, this serves as a massive hint. In the worst-case scenario, every parenthesis presents two choices: either we keep it or we remove it. This forms a decision tree with a time complexity of $O(2^n)$. For $n = 20$, $2^{20}$ is roughly $10^6$ operations. This small constraint confirms that exploring all possibilities using an exponential approach like **Backtracking** is optimal and perfectly safe from Time Limit Exceeded (TLE) errors.

Characters (alphabets) have no effect on the validity of the parentheses, meaning whenever we encounter a character, we have no choice but to include it in our current string and move forward. 

---

## 🧠 Approach

We use **Backtracking** to generate all combinations while implementing smart pruning to optimize our solution.

1. **State Tracking:** Maintain a `count` variable. Adding an open bracket `(` increments the count by 1, and adding a closing bracket `)` decrements it by 1. 
2. **Early Pruning (Invalidation):** At any point, if `count < 0`, the string has more closing brackets than opening ones. It is permanently invalid. We can safely prune this branch and return early without exploring further.
3. **On-the-Fly Max Length Tracking:** We must find strings with the *minimum* removals, which translates to finding valid strings with the *maximum* length. Instead of storing all balanced strings in a set and filtering the longest ones later, we track `maxLen` dynamically during the recursive calls:
   - If we reach the end of the string and find a valid sequence (`count == 0`), we check its length.
   - If `curr.length() > maxLen`, it means we've found a better answer (fewer removals). We clear our result set, update `maxLen`, and add this new string.
   - If `curr.length() == maxLen`, it's an equally optimal answer, so we simply add it to the set.

---

## 💻 Solution Code 

### Brute-force Solution (Conceptual)
A pure brute-force generation would explore all $O(2^n)$ subsets, add them to a massive list, check each one at the end to see if it has balanced parentheses, find the maximum length among all valid strings, and finally push only those matching the maximum length into a unique set. This requires immense auxiliary space and redundant processing for clearly invalid strings. 

### Optimized Solution (C++)
The code below implements the highly optimized backtracking template, complete with early pruning and on-the-fly max length filtering.

```cpp
// Intuition: Since constraints are extremely small (at most 20 parentheses), we can use backtracking to explore taking or dropping each parenthesis. By actively checking validity and tracking max length dynamically, we find optimal solutions efficiently.
// Approach: 
// 1. Keep a `count` of brackets (open = +1, close = -1). If `count < 0`, prune immediately.
// 2. Track `maxLen` to keep only the longest valid strings on-the-fly.
// 3. If the character is a letter, always add it.
// 4. If it's a parenthesis, branch out: one recursive call includes it, the other excludes it.
// Time Complexity: O(2^n), where n is the number of parentheses in worst case. Max 2^20 is approx 10^6 ops.
// Space Complexity: O(M * N), where M is the total valid strings stored in the set, and N is the average length of each string.

class Solution {
private:
    unordered_set<string> st;
    int n;

    void solve(const string& s, int i, string& curr, int count, int& maxLen) {
        if (count < 0)  // Early pruning: sequence has become invalid
            return;

        if (i == n) {
            if (count == 0) { // Found a perfectly balanced parenthesis string
                if (curr.length() > maxLen) {        // Found a longer valid string (fewer removals)
                    maxLen = curr.length();
                    st.clear(); // Clear out previous shorter strings
                }
                
                if(curr.length() == maxLen) { // Add to result if length matches the optimal found so far
                    st.insert(curr);
                }
                
            }
            return;
        }

        if (s[i] != '(' && s[i] != ')') {                     // Letter: always keep and move forward
            curr.push_back(s[i]);
            solve(s, i + 1, curr, count, maxLen);
            curr.pop_back(); // Backtrack
            return;
        }

        // Do: Choice 1 - Include the current parenthesis
        curr.push_back(s[i]);

        // Explore with the parenthesis included
        solve(s, i + 1, curr, count + (s[i] == '(' ? 1 : -1), maxLen);

        // Undo and explore: Choice 2 - Exclude the current parenthesis
        curr.pop_back(); 
        solve(s, i + 1, curr, count, maxLen);
    }

public:
    vector<string> removeInvalidParentheses(string s) {
        n = s.length();
        int maxLen = 0;
        st.clear();

        string curr = "";
        solve(s, 0, curr, 0, maxLen);

        return vector<string>(begin(st), end(st));
    }
};

/*
*
* Dry Run
* s = "()())()"
* - Starting at i = 0, count = 0, curr = ""
* - Include '(': curr = "(", count = 1
*   - Include ')': curr = "()", count = 0
*     - Include '(': curr = "()(", count = 1
*       - Include ')': curr = "()()", count = 0
*         - Exclude ')' (the extra one): curr = "()()", count = 0
*           - Include '(': curr = "()()(", count = 1
*             - Include ')': curr = "()()()", count = 0. Reached end. maxLen = 6. Insert to set.
* - Backtrack to the extra closing parenthesis.
* - Include it: curr="()())", count = -1. Pruned immediately!
* - Explore other branches (e.g., skipping the first closing bracket).
* - Max length string found is 6. Final unique set contains: ["(())()", "()()()"].
*
*/
```

## 📌 Notes
- **Early Pruning** is critical for problems with exponential complexity. Returning early when `count < 0` drastically reduces the recursion tree.
- A hash set (`unordered_set`) is naturally required because different deletion paths might result in the exact same output string, and the problem strictly requires unique answers.

---

## 🔍 Key Insights
- **Constraint-Driven Intuition:** The constraint of maximum 20 parentheses is a massive giveaway that an $O(2^n)$ algorithm is not only acceptable but expected. Recognizing this saves time from trying to invent complex dynamic programming or greedy solutions.
- **On-the-Fly Max Length:** Using the `maxLen` variable to automatically wipe the storage set (`st.clear()`) when a better answer is found is a beautiful pattern. It eliminates the need for a secondary iteration through thousands of generated strings to find the longest ones.
